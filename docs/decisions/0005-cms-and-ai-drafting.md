# ADR 0005: ระบบแก้ไขเนื้อหาสำหรับครู (Decap CMS) และคิวร่างโจทย์ด้วย AI

- สถานะ: ยอมรับแล้ว
- วันที่: 23 ต.ค. 2569

## บริบท

แผนเดิมวางไว้ว่าเฟส 4 จะใช้ Payload CMS แต่ Payload ต้องมีฐานข้อมูลและเซิร์ฟเวอร์ Node ของตัวเอง แล้วต้อง export กลับเป็นไฟล์ YAML ทำให้มีแหล่งความจริงสองที่ ซึ่งไม่คุ้มสำหรับโครงการที่ไม่หารายได้และมีผู้ดูแลน้อย

## การตัดสินใจ

1. **ใช้ Decap CMS (MIT)** เป็นหน้าเว็บแก้ไขที่ `/admin/` โดยแก้ไฟล์ใน Git โดยตรง
   - ไม่มีเซิร์ฟเวอร์หรือฐานข้อมูลเพิ่ม
   - ทุกการแก้ไขกลายเป็น Pull Request (`publish_mode: editorial_workflow`) แล้ว CI รัน `npm run validate` ก่อน merge เหมือนงานที่เขียนด้วยมือ
   - การตั้งค่า (`public/admin/config.yml`) สร้างจาก `content/subjects.yaml` ด้วย `apps/web/scripts/cms-config.mjs` ทุกครั้งที่ build จึงตรงกับ schema เสมอ
   - แต่ละวิชามี 3 คอลเลกชัน: หัวข้อ, บทเรียน (Markdown), ชุดโจทย์ (รายการโจทย์ที่เลือกชนิดได้)
   - ปิดการสร้างและลบหัวข้อผ่าน CMS เพราะรหัสหัวข้อผูกกับความคืบหน้าของผู้เรียน หัวข้อใหม่ให้สร้างตามคู่มือผู้เขียนแล้วเปิด PR
   - สื่อโต้ตอบ (`widget`) มีโครงซ้อนลึก ให้แก้ใน YAML โดยตรง CMS แก้ได้เฉพาะชื่อและคำบรรยาย (Decap คงฟิลด์ที่ไม่ได้ประกาศไว้)
   - ตัวโหลดเนื้อหาตัด front matter ว่างที่ Decap อาจเติมให้ไฟล์ .md
   - หน้า `/admin/` ถูกลบออกจากแอป Android ตอน `npm run android:sync`
2. **คิวร่างโจทย์ด้วย AI** (`npm run draft -- <วิชา/โฟลเดอร์> --count=5`)
   - ส่งบทเรียนและโจทย์เดิมของหัวข้อให้ Claude ร่างโจทย์ใหม่เป็น JSON ตาม schema (structured outputs) ตั้ง effort สูงเพราะความถูกต้องของเฉลยสำคัญที่สุด
   - แปลงและตรวจด้วย schema เดียวกับงานที่คนเขียน ข้อที่ไม่ผ่านถูกตัดทิ้งพร้อมเหตุผล
   - บันทึกที่ `content/_drafts/<วิชา>/<โฟลเดอร์>/problems.yaml` ซึ่งแอปไม่โหลด (โฟลเดอร์ขึ้นต้นด้วย `_`) ทุกข้อติด `ai_assisted: true`
   - ผู้ตรวจต้องคำนวณตัวเลขทุกข้อใหม่เอง แก้ไข แล้วรัน `npm run approve -- <วิชา/โฟลเดอร์> [--ids=...]` เพื่อย้ายเข้าคลัง จากนั้นเปิด PR ตามปกติ
   - เปลี่ยนสถานะหัวข้อเป็น `published` ได้เมื่อมีผู้ตรวจที่เป็นคนลงชื่อใน `reviewed_by` เท่านั้น

## ผลที่ตามมา

- ครูต้องมีบัญชี GitHub และสิทธิ์ในรีโพ (หรือใช้ Decap ผ่าน Git Gateway / OAuth proxy ภายหลัง) ดู `docs/setup/cms.md`
- ไม่มีหน้าจัดการผู้ใช้ในตัว สิทธิ์ครูจัดผ่าน GitHub และตาราง `staff` ใน Supabase (สำหรับหน้าคุณภาพและรายงานโจทย์)
