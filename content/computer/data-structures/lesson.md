## แอปโรงอาหารใช้โครงสร้างข้อมูลอะไรบ้าง

แอปสั่งอาหารของโรงอาหารโรงเรียนต้องเรียงคำสั่งซื้อตามลำดับที่เข้ามา ปุ่มย้อนกลับต้องพาไปหน้าที่เพิ่งเปิด ต้องหาเมนูจากรหัสได้ทันทีแม้มีหลายพันเมนู และต้องบอกทางเดินที่สั้นที่สุดจากประตูไปจุดรับอาหาร งานแต่ละอย่างเหมาะกับ **โครงสร้างข้อมูล (data structure)** คนละแบบ บท [ลิสต์ ดิกชันนารี และข้อความ](/topic/computer.programming.lists-strings/) และ [การค้นหาและการเรียงลำดับ](/topic/computer.algorithms.searching-sorting/) ใช้ลิสต์เป็นหลัก บทนี้รู้จักอีกห้าแบบ และเลือกใช้ให้เหมาะกับงาน

## ชนิดข้อมูลนามธรรม

**ชนิดข้อมูลนามธรรม (abstract data type)** บอกว่าโครงสร้างนั้น **ทำอะไรได้** เช่น "คิวเพิ่มที่ท้ายและเอาออกที่หัว" โดยยังไม่บอกว่าเก็บในหน่วยความจำ **อย่างไร** ผู้ใช้จึงคิดถึงการทำงานได้โดยไม่ต้องรู้รายละเอียดข้างใน และเปลี่ยนวิธีเก็บให้เร็วขึ้นได้โดยโค้ดที่เรียกใช้ไม่ต้องแก้

## สแตก: เข้าทีหลัง ออกก่อน

**สแตก (stack)** เหมือนกองจาน วางจานใบใหม่ไว้บนสุด (**push**) และหยิบใบบนสุดออก (**pop**) จึงเป็นแบบ **เข้าทีหลังออกก่อน (LIFO)** (ดูภาพ) ใน Python ใช้ลิสต์ได้เลย `append` คือ push และ `pop()` คือ pop ทั้งคู่ใช้เวลา $O(1)$ สแตกใช้ในปุ่มย้อนกลับของเบราว์เซอร์ การยกเลิกการทำ (undo) กองการเรียกฟังก์ชัน และการตรวจวงเล็บ

```python
def balanced(text):
    pairs = {")": "(", "]": "[", "}": "{"}
    stack = []
    for ch in text:
        if ch in "([{":
            stack.append(ch)                 # push
        elif ch in pairs:
            if not stack or stack.pop() != pairs[ch]:
                return False                 # ปิดโดยไม่มีคู่ หรือคู่ไม่ตรง
    return len(stack) == 0                   # ต้องไม่เหลือวงเล็บเปิดค้าง

print(balanced("(a[1] + b) * {c}"))   # True
print(balanced("(]"))                 # False
```

## คิว: เข้าก่อน ออกก่อน

**คิว (queue)** เหมือนแถวรอซื้ออาหาร เข้าที่ท้ายคิว (**enqueue**) และออกที่หัวคิว (**dequeue**) จึงเป็นแบบ **เข้าก่อนออกก่อน (FIFO)** ถ้าใช้ลิสต์ `pop(0)` ต้องเลื่อนทุกตัวที่เหลือมาข้างหน้า ใช้เวลา $O(n)$ จึงควรใช้ `deque` ที่เอาออกจากหัวได้ใน $O(1)$

```python
from collections import deque
q = deque()
q.append("A01")
q.append("A02")
q.append("A03")
print(q.popleft())   # A01
print(len(q))        # 2
```

## ตารางแฮช: ค้นด้วยคีย์ทันที

**ตารางแฮช (hash table)** ใช้ **ฟังก์ชันแฮช** แปลงคีย์เป็นเลขช่อง แล้วเก็บข้อมูลไว้ในช่องนั้น เช่น $h(k) = k \bmod 7$ รหัส 6503 ไปช่อง 0 (ดูภาพ) เมื่อค้นก็คำนวณช่องแล้วดูเฉพาะช่องนั้น ใช้เวลาเฉลี่ย $O(1)$ ไม่ว่าจะมีข้อมูลมากเท่าไร ถ้าสองคีย์ได้ช่องเดียวกันเรียกว่า **การชนกัน (collision)** แก้ได้ เช่น ต่อเป็นลิสต์ในช่องนั้น ดิกชันนารีและเซตของ Python คือตารางแฮช ข้อจำกัดคือข้อมูลไม่เรียงตามคีย์ จึงตอบคำถามแบบช่วง เช่น "รหัส 6500 ถึง 6520" ได้ไม่ดี และคีย์ต้องเปลี่ยนค่าไม่ได้ (ใช้ลิสต์เป็นคีย์ไม่ได้)

## ต้นไม้ค้นหาแบบทวิภาค

**ต้นไม้ (tree)** มี **ราก (root)** แต่ละ **โหนด (node)** มี **ลูก (child)** และโหนดที่ไม่มีลูกเรียกว่า **ใบ (leaf)** **ต้นไม้ค้นหาแบบทวิภาค (binary search tree)** มีลูกไม่เกินสอง และทุกโหนดมีค่าทางซ้ายน้อยกว่า ค่าทางขวามากกว่าหรือเท่ากับ การค้นจึงเริ่มที่ราก เทียบแล้วลงซ้ายหรือขวา (ดูภาพ) จำนวนครั้งที่เทียบไม่เกินความสูงของต้นไม้ ถ้าต้นไม้สมดุลจะสูงราว $\log_2 n$ แต่ถ้าใส่ข้อมูลที่เรียงแล้วตามลำดับ ต้นไม้จะเอียงเป็นเส้นตรง สูง $n$ และช้าเท่าลิสต์ ข้อดีเหนือตารางแฮชคือไล่ค่าจากน้อยไปมากได้ และตอบคำถามแบบช่วงได้

```python
def insert(node, key):
    if node is None:
        return {"key": key, "left": None, "right": None}
    if key < node["key"]:
        node["left"] = insert(node["left"], key)
    else:
        node["right"] = insert(node["right"], key)
    return node

def contains(node, key):
    while node is not None:
        if key == node["key"]:
            return True
        node = node["left"] if key < node["key"] else node["right"]
    return False

root = None
for k in [50, 30, 70, 20, 40, 60, 80]:
    root = insert(root, k)
print(contains(root, 60), contains(root, 65))   # True False
```

## กราฟและการท่องกราฟ

**กราฟ (graph)** มี **จุดยอด (vertex)** และ **เส้นเชื่อม (edge)** เส้นเชื่อมอาจมีทิศทาง (ถนนเดินรถทางเดียว) หรือมีน้ำหนัก (ระยะทาง) ก็ได้ แทนกราฟได้สองแบบ (ดูภาพ)

- **ลิสต์ประชิด (adjacency list)** เก็บรายชื่อเพื่อนบ้านของแต่ละจุด ใช้ที่ราว $V + 2E$ ช่องสำหรับกราฟไม่มีทิศทาง เหมาะกับกราฟที่เส้นเชื่อมไม่หนาแน่น
- **เมทริกซ์ประชิด (adjacency matrix)** ตาราง $V \times V$ ช่อง ใส่ 1 เมื่อสองจุดเชื่อมกัน ตรวจว่าสองจุดเชื่อมกันหรือไม่ได้ทันที แต่ใช้ที่ $V^2$ เสมอ

**การท่องแบบกว้างก่อน (breadth-first search, BFS)** ใช้คิว ไปทุกจุดที่ห่าง 1 เส้นก่อน แล้วจึงไปจุดที่ห่าง 2 เส้น จึงได้จำนวนเส้นเชื่อมที่น้อยที่สุดจากจุดเริ่มต้นไปทุกจุด **การท่องแบบลึกก่อน (depth-first search, DFS)** ใช้สแตก (หรือการเรียกซ้ำ) เดินลึกไปทางหนึ่งจนสุดแล้วจึงย้อนกลับ เหมาะกับการสำรวจทุกเส้นทาง เช่น หาทางออกจากเขาวงกต

```python
graph = {
    "ประตู": ["อาคาร 1", "โรงอาหาร"],
    "อาคาร 1": ["ประตู", "ห้องสมุด"],
    "โรงอาหาร": ["ประตู", "ห้องสมุด", "สนาม"],
    "ห้องสมุด": ["อาคาร 1", "โรงอาหาร", "หอประชุม"],
    "สนาม": ["โรงอาหาร", "หอประชุม"],
    "หอประชุม": ["ห้องสมุด", "สนาม"],
}

def bfs(graph, start):
    dist = {start: 0}
    q = deque([start])
    while q:
        v = q.popleft()
        for w in graph[v]:
            if w not in dist:
                dist[w] = dist[v] + 1
                q.append(w)
    return dist

def dfs(graph, start):
    seen, stack = [], [start]
    while stack:
        v = stack.pop()
        if v not in seen:
            seen.append(v)
            for w in reversed(graph[v]):     # กลับด้านเพื่อให้ไปเพื่อนบ้านตัวแรกก่อน
                stack.append(w)
    return seen

print(bfs(graph, "ประตู")["หอประชุม"])   # 3
print(dfs(graph, "ประตู"))
# ['ประตู', 'อาคาร 1', 'ห้องสมุด', 'โรงอาหาร', 'สนาม', 'หอประชุม']
```

## เลือกโครงสร้างให้เหมาะกับงาน

| งาน | โครงสร้างที่เหมาะ | เวลาโดยประมาณ |
|---|---|---|
| ย้อนกลับ ยกเลิกการทำ | สแตก | push/pop $O(1)$ |
| ให้บริการตามลำดับที่มา | คิว (`deque`) | เข้า/ออก $O(1)$ |
| ค้นด้วยรหัสหรือชื่อ | ตารางแฮช (`dict`, `set`) | เฉลี่ย $O(1)$ |
| ค้นและไล่ตามลำดับ ค้นเป็นช่วง | ต้นไม้ค้นหาแบบทวิภาคที่สมดุล | $O(\log n)$ |
| ความสัมพันธ์และเส้นทาง | กราฟ + BFS หรือ DFS | $O(V + E)$ |

## ข้อผิดพลาดที่พบบ่อย

- **สลับสแตกกับคิว** สแตกเอาตัวที่ใส่ล่าสุดออก คิวเอาตัวที่ใส่ก่อนสุดออก
- **ใช้ `list.pop(0)` ทำคิวยาว ๆ** ทุกครั้งต้องเลื่อนสมาชิกที่เหลือทั้งหมด
- **คิดว่าต้นไม้ค้นหาเร็วเสมอ** ถ้าเอียงจะช้าเท่าลิสต์
- **ใช้ DFS หาเส้นทางที่ผ่านน้อยเส้นที่สุด** DFS ไม่รับประกัน ต้องใช้ BFS
- **ใช้เมทริกซ์ประชิดกับกราฟใหญ่ที่เชื่อมกันน้อย** เปลืองหน่วยความจำมาก
