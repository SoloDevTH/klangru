## จากสมุดบัญชีสู่ระบบ

ร้านวัสดุก่อสร้างของคุณพ่อนก (สมมติ) เคยจดบิลขายในสมุด สิ้นเดือนต้องนั่งรวมยอดลูกหนี้ทีละหน้า และพบบ่อยว่ายอดในสมุดไม่ตรงกับเงินในบัญชีธนาคาร เมื่อเปลี่ยนมาใช้โปรแกรมบัญชี บิลขายแต่ละใบถูกบันทึกครั้งเดียวแล้วไปปรากฏในบัญชีลูกหนี้ สต็อกสินค้า และงบการเงินพร้อมกัน แต่โปรแกรมก็ทำให้เกิดความเสี่ยงใหม่ เช่น ใครก็แก้ข้อมูลได้ถ้ารหัสผ่านรั่ว นี่คือเรื่องของ **ระบบสารสนเทศทางการบัญชี (AIS)**

## ส่วนประกอบและการไหลของข้อมูล

AIS ประกอบด้วย **คน** (ผู้บันทึก ผู้อนุมัติ ผู้ใช้รายงาน) **วิธีปฏิบัติงาน** **ข้อมูล** **ซอฟต์แวร์** **โครงสร้างพื้นฐานด้านไอที** และ **การควบคุมภายใน** ข้อมูลไหลเป็นสามขั้น

1. **นำเข้า** จากเอกสารขั้นต้น เช่น ใบสั่งซื้อ ใบกำกับภาษี ใบเสร็จรับเงิน สลิปโอนเงิน
2. **ประมวลผล** บันทึกรายการ ผ่านไปบัญชีแยกประเภท ปรับปรุงยอด ตามหลักใน [การบันทึกบัญชีคู่](/topic/business.accounting.double-entry/)
3. **แสดงผล** รายงานและงบการเงิน เช่น งบทดลอง รายงานลูกหนี้แยกตามอายุ รายงานยอดขายตามสินค้า

ข้อมูลแบ่งเป็น **แฟ้มข้อมูลหลัก** (เปลี่ยนไม่บ่อย เช่น ผังบัญชี รายชื่อลูกค้าและวงเงินเครดิต รายการสินค้า) และ **แฟ้มรายการ** (เกิดทุกวัน เช่น บิลขาย ใบจ่ายเงิน)

## วงจรธุรกิจในโปรแกรมบัญชี

| วงจร | ขั้นตอนหลัก | โมดูลที่เกี่ยวข้อง |
|---|---|---|
| **รายได้** | รับคำสั่งซื้อ → ตรวจวงเงินเครดิต → ส่งของ → ออกใบแจ้งหนี้ → รับชำระ | ขาย ลูกหนี้ สต็อก |
| **ค่าใช้จ่าย** | ขอซื้อ → สั่งซื้อ → รับของ → รับใบแจ้งหนี้ → จ่ายเงิน | ซื้อ เจ้าหนี้ สต็อก |
| **การผลิตและสินค้า** | เบิกวัตถุดิบ → ผลิต → รับสินค้าเข้าคลัง | สต็อก ต้นทุน |
| **เงินเดือน** | บันทึกเวลาทำงาน → คำนวณค่าจ้าง → จ่าย → นำส่งภาษีและประกันสังคม | เงินเดือน |
| **บัญชีแยกประเภทและรายงาน** | รับข้อมูลจากทุกวงจร → ปรับปรุง → ปิดบัญชี → งบการเงิน | บัญชีแยกประเภททั่วไป |

## ทำบัญชีด้วยสเปรดชีต

กิจการเล็กจำนวนมากใช้สเปรดชีต วางแผ่นงาน **ผังบัญชี** (รหัส ชื่อบัญชี) และแผ่นงาน **สมุดรายวัน** หนึ่งแถวต่อหนึ่งบรรทัดรายการ (วันที่ เลขที่เอกสาร รหัสบัญชี เดบิต เครดิต) แล้วใช้สูตร

- `=VLOOKUP(C2,ผังบัญชี!$A$2:$B$9,2,FALSE)` ดึงชื่อบัญชีจากรหัสใน C2 (`FALSE` คือหาเฉพาะรหัสที่ตรงพอดี)
- `=SUMIF(C$2:C$100,101,D$2:D$100)-SUMIF(C$2:C$100,101,E$2:E$100)` ยอดคงเหลือบัญชีเงินสด (รหัส 101) = เดบิตรวม − เครดิตรวม
- `=SUM(D2:D100)-SUM(E2:E100)` ถ้าไม่เป็นศูนย์ แปลว่าบันทึกไม่สมดุล
- `=IF(ABS(SUM(D2:D100)-SUM(E2:E100))<0.01,"สมดุล","ตรวจสอบ")` ให้แผ่นงานเตือนเอง

เครื่องหมาย `$` ทำให้การอ้างอิงคงที่เมื่อคัดลอกสูตรไปแถวอื่น ตารางสรุป (Pivot Table) ใช้รวมยอดตามบัญชีหรือตามเดือนได้เร็ว แต่สเปรดชีตแก้ไขง่ายและไม่มีประวัติการแก้ไขที่รัดกุมเท่าโปรแกรมบัญชี จึงต้องมีการควบคุมเพิ่ม

## การควบคุมทั่วไปและการควบคุมระบบงาน

**การควบคุมทั่วไป** ดูแลสภาพแวดล้อมของระบบทั้งหมด ใช้กับทุกโปรแกรม

- กำหนดรหัสผู้ใช้และสิทธิตามหน้าที่ ห้ามใช้รหัสผ่านร่วมกัน
- **แบ่งแยกหน้าที่** คนอนุมัติจ่ายเงิน คนบันทึกบัญชี และคนถือเงินไม่ควรเป็นคนเดียวกัน
- สำรองข้อมูลสม่ำเสมอและทดสอบการกู้คืน
- ควบคุมการแก้ไขโปรแกรม และป้องกันห้องเครื่องหรือบัญชีคลาวด์

**การควบคุมระบบงาน** ฝังอยู่ในแต่ละงาน เช่น งานขายหรือเงินเดือน

- **ควบคุมการนำเข้า** ตรวจรูปแบบข้อมูล (ช่องจำนวนเงินต้องเป็นตัวเลข) ตรวจขอบเขต (ชั่วโมงทำงานไม่เกินที่กำหนด) ตรวจความครบถ้วน เอกสารเรียงเลขที่ **หลักตรวจสอบ (check digit)** ในรหัสลูกค้า และ **ยอดรวมควบคุม** ของเอกสารทั้งชุด
- **ควบคุมการประมวลผล** เทียบยอดก่อนและหลังประมวลผล จับคู่ใบสั่งซื้อ ใบรับของ และใบแจ้งหนี้
- **ควบคุมผลลัพธ์** กระทบยอดรายงานกับแหล่งอื่น เช่น ยอดเงินฝากกับรายการเดินบัญชีธนาคาร และจำกัดผู้รับรายงาน

## ใช้ข้อมูลช่วยตัดสินใจ

ข้อมูลที่บันทึกถูกต้องนำไปวิเคราะห์ได้ เช่น รายงานลูกหนี้แยกตามอายุบอกว่าควรตามหนี้รายใดก่อน อัตรากำไรขั้นต้นรายสินค้าบอกว่าควรส่งเสริมสินค้าใด เทคโนโลยีดิจิทัลช่วยให้งานบัญชีเร็วและแม่นขึ้น เช่น ใบกำกับภาษีอิเล็กทรอนิกส์ (e-Tax Invoice) การดึงรายการธนาคารเข้าระบบอัตโนมัติ การอ่านเอกสารด้วย OCR และโปรแกรมบัญชีบนคลาวด์ ทั้งนี้ต้องดูแลข้อมูลส่วนบุคคลของลูกค้าและพนักงานตามกฎหมายคุ้มครองข้อมูลส่วนบุคคลด้วย

## ข้อผิดพลาดที่พบบ่อย

- **คิดว่าโปรแกรมทำให้ข้อมูลถูกเสมอ** ถ้านำเข้าผิด ผลลัพธ์ก็ผิด (garbage in, garbage out)
- **สับสนการควบคุมสองแบบ** การสำรองข้อมูลและรหัสผ่านเป็นการควบคุมทั่วไป การตรวจขอบเขตของช่องข้อมูลเป็นการควบคุมระบบงาน
- **ลืม `$`** คัดลอกสูตรแล้วช่วงอ้างอิงเลื่อนตาม ทำให้ VLOOKUP หาไม่เจอ
- **ใช้ VLOOKUP แบบประมาณค่า** ถ้าละ `FALSE` ไว้ รหัสที่ไม่มีอยู่จริงอาจได้ชื่อบัญชีที่ใกล้เคียงแทนที่จะแจ้งข้อผิดพลาด
