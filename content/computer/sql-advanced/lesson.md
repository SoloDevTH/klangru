## ขายได้เท่าไรและใครขายได้มากที่สุด

ร้านขนมของโรงเรียนจดการขายทุกรายการไว้ในตาราง `sales` ครูอยากรู้ว่าแต่ละคนขายได้รวมเท่าไร และอยากเห็นเฉพาะคนที่ขายได้มากพอ คำถามเหล่านี้ต้องใช้ SQL ระดับที่สูงกว่าการเลือกแถวธรรมดา บทนี้จะฝึกการจัดกลุ่ม การรวมข้อมูล การเชื่อมตารางแบบไม่ทิ้งแถว การแก้ไขข้อมูลอย่างปลอดภัย และแนวคิดว่าระบบฐานข้อมูลทำงานอย่างไรภายใน

ในแอปนี้ไม่มีการรันคำสั่ง SQL จริง บทนี้จึงเน้นการอ่านผลลัพธ์ การเรียงลำดับคำสั่ง และการจำลองด้วย Python ที่ใช้ไลบรารีมาตรฐาน

## จัดกลุ่มแล้วสรุป

`GROUP BY` แบ่งแถวที่มีค่าเหมือนกันในคอลัมน์ที่ระบุให้เป็นกลุ่ม แล้วใช้ฟังก์ชันรวม เช่น `COUNT`, `SUM` และ `AVG` คำนวณแยกแต่ละกลุ่ม

```sql
SELECT seller, SUM(qty) FROM sales GROUP BY seller;
```

ถ้าต้องการกรองกลุ่มตามผลของฟังก์ชันรวม ให้ใช้ `HAVING` ไม่ใช่ `WHERE` เพราะ `WHERE` กรองแถวก่อนจัดกลุ่ม ส่วน `HAVING` กรองหลังจัดกลุ่มแล้ว ลำดับการประมวลผลเชิงตรรกะคือ FROM แล้ว WHERE แล้ว GROUP BY แล้ว HAVING แล้ว SELECT และสุดท้าย ORDER BY ดังภาพ


## ค่า NULL ไม่ใช่ศูนย์

`NULL` หมายถึงไม่มีค่าหรือยังไม่ทราบค่า ไม่เท่ากับ 0 และไม่เท่ากับสตริงว่าง การเปรียบเทียบกับ `NULL` ด้วย `=` ได้ผลเป็น UNKNOWN (ไม่จริงและไม่เท็จ) แถวนั้นจึงไม่ถูกเลือก ต้องใช้ `IS NULL` แทน `COUNT(*)` นับทุกแถว ส่วน `COUNT(price)` นับเฉพาะแถวที่ `price` ไม่เป็น `NULL` ฟังก์ชัน `SUM` และ `AVG` ก็ข้าม `NULL` เช่นกัน

## เชื่อมตารางโดยไม่ทิ้งแถว

ตาราง `sellers` เก็บรายชื่อผู้ขายทุกคนและโซน ถ้าใช้ `INNER JOIN` จะได้เฉพาะผู้ขายที่มีรายการขาย แต่ `LEFT JOIN` เก็บทุกแถวจากตารางซ้ายไว้ แม้ไม่มีคู่ในตารางขวา คอลัมน์ฝั่งขวาจะเป็น `NULL` เมื่อไม่มีคู่ การนับจำนวนรายการขายต่อคนจึงควรใช้ `COUNT(sa.id)` เพราะจะได้ศูนย์ให้ผู้ขายที่ไม่มีรายการ ไม่ใช่หายไปจากผลลัพธ์

## เพิ่ม แก้ และลบข้อมูล

- `INSERT` เพิ่มแถวใหม่ ระบุคอลัมน์ให้ชัดเจนเพื่อไม่ให้ลำดับคอลัมน์ผิด
- `UPDATE` แก้ค่าในแถว ต้องมี `WHERE` เสมอ เพราะ `UPDATE sales SET price = 0` ที่ไม่มี `WHERE` จะแก้ทุกแถวในตาราง
- `DELETE` ลบแถว ใช้หลักเดียวกับ `UPDATE`

วิธีปลอดภัยคือเริ่มธุรกรรมด้วย `BEGIN` รันคำสั่งที่มี `WHERE` ตรวจผลด้วย `SELECT` แล้วจึงยืนยันด้วย `COMMIT` หรือย้อนกลับด้วย `ROLLBACK` ถ้าผลผิด

## กฎของตาราง

`PRIMARY KEY` ระบุว่าค่าในคอลัมน์นี้ไม่ซ้ำและไม่เป็น `NULL` ส่วน `FOREIGN KEY` บังคับว่าค่าในคอลัมน์ต้องมีอยู่จริงในตารางอ้างอิง เช่น คอลัมน์ `seller` ในตาราง `sales` ต้องเป็นชื่อที่มีใน `sellers` ทำให้ไม่เกิดรายการขายของคนที่ไม่มีอยู่จริง ข้อจำกัดอื่นได้แก่ `NOT NULL` และ `UNIQUE`

## ระบบประมวลผลคำสั่งอย่างไร

เมื่อสั่ง `SELECT` ระบบจะสร้าง **แผนการทำงาน (query plan)** ซึ่งเลือกวิธีอ่านข้อมูล ถ้าไม่มีดัชนี ระบบต้อง **สแกนทั้งตาราง** อ่านทีละแถว แต่ถ้ามี **ดัชนีแบบต้นไม้ B (B-tree)** ระบบเดินจากรากลงสู่ใบ อ่านเพียงไม่กี่โหนดก็หาค่าได้ ดังภาพ


การเชื่อมตารางก็มีวิธีที่ต่างกัน เช่น **วงวนซ้อน** ที่เทียบทุกคู่แถว เหมาะกับตารางเล็ก และ **การ JOIN แบบแฮช** ที่สร้างตารางแฮชจากตารางหนึ่งแล้วค้นหาจากอีกตาราง เหมาะกับตารางขนาดใหญ่ที่เชื่อมด้วยค่าที่เท่ากัน

## ธุรกรรม ACID และการแก้พร้อมกัน

**ธุรกรรม (transaction)** คือกลุ่มคำสั่งที่ต้องสำเร็จทั้งหมดหรือไม่เกิดอะไรเลย สมบัติ ACID มีสี่ข้อ ได้แก่

- **Atomicity** ทำทั้งหมดหรือไม่ทำเลย
- **Consistency** ข้อมูลหลังธุรกรรมยังเป็นไปตามกฎของตาราง
- **Isolation** ธุรกรรมที่ทำพร้อมกันไม่รบกวนกัน ผลออกมาเหมือนทำทีละธุรกรรม
- **Durability** เมื่อยืนยันแล้ว ผลจะคงอยู่แม้ระบบดับ

เมื่อผู้ขายสองคนแก้ยอดเดียวกันพร้อมกัน เช่น ทั้งคู่อ่านยอดคงเหลือ 10 ชิ้น แล้วต่างคนต่างหักออก 1 ชิ้นและเขียนกลับเป็น 9 ยอดที่ถูกควรเป็น 8 แต่การแก้ของคนแรกหายไป ระบบจึงใช้การล็อกให้ธุรกรรมที่สองรอจนธุรกรรมแรกเสร็จ เพื่อไม่ให้ทับกันโดยไม่ตั้งใจ และใช้**บันทึกการเปลี่ยนแปลงล่วงหน้า (write-ahead log)** เพื่อกู้คืนได้หลังระบบล่ม โดยเล่าซ้ำการเปลี่ยนแปลงที่ยืนยันแล้วและย้อนรายการที่ยังไม่ยืนยัน

## ข้อผิดพลาดที่พบบ่อย

- ใช้ `WHERE` กับฟังก์ชันรวม เช่น `WHERE SUM(qty) > 5` ซึ่งต้องย้ายไปเป็น `HAVING`
- เขียน `price = NULL` แล้วคาดว่าจะหาแถวที่เป็นค่าว่าง ที่ถูกคือ `price IS NULL`
- ลืม `WHERE` ใน `UPDATE` หรือ `DELETE` ทำให้ทุกแถวเปลี่ยน
- ใช้ `INNER JOIN` แล้วหายผู้ขายที่ไม่มีรายการขาย ทั้งที่ควรเห็นเป็นศูนย์
