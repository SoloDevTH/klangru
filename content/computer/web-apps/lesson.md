## กดปุ่มแล้วรายการเปลี่ยนทันที

ร้านขนมของโรงเรียนมีเว็บสั่งจองขนม นักเรียนกดปุ่ม "เพิ่มในตะกร้า" แล้วตัวเลขจำนวนสินค้าเปลี่ยนทันที โดยหน้าไม่กระพริบโหลดใหม่ทั้งหน้า สิ่งที่ทำให้เกิดเหตุการณ์นี้คือการทำงานร่วมกันของ **ฝั่งลูกข่าย (client)** ซึ่งคือเบราว์เซอร์ และ **ฝั่งแม่ข่าย (server)** ซึ่งเก็บข้อมูลจริง บทนี้อธิบายว่าสองฝั่งนี้คุยกันอย่างไร และทำไมเว็บแอปจึงต้องออกแบบให้ใช้ได้กับทุกขนาดจอและทุกคน

## หน้าที่ของ HTML CSS และ JavaScript

- **HTML** กำหนดโครงสร้างของเนื้อหา เช่น หัวข้อ ปุ่ม ช่องกรอก
- **CSS** กำหนดรูปลักษณ์ เช่น สี ขนาด และตำแหน่ง
- **JavaScript** ทำให้หน้าเปลี่ยนตามการกระทำของผู้ใช้

JavaScript อ่านและแก้ไขโครงสร้างของหน้าผ่าน **DOM** (Document Object Model) ซึ่งเป็นต้นไม้ของแท็กในหน้า เช่น โค้ด `document.querySelector("#count").textContent = 3` เปลี่ยนตัวเลขที่แสดง เมื่อผู้ใช้กดปุ่ม **ตัวจัดการเหตุการณ์ (event handler)** จะรันฟังก์ชันที่เรากำหนดไว้

## HTTP: ภาษาที่เบราว์เซอร์คุยกับเซิร์ฟเวอร์

ทุกคำขอบนเว็บใช้ HTTP ซึ่งมีคำขอ (request) และคำตอบ (response) คำขอระบุ **เมธอด** และ **ทรัพยากร** (path) เช่น `GET /api/items` หมายถึง "ขออ่านรายการ" ส่วนเมธอดหลักที่ใช้บ่อยมีดังนี้

- `GET` ขออ่านข้อมูลและไม่เปลี่ยนแปลงอะไรบนเซิร์ฟเวอร์ (เป็น safe method)
- `POST` ส่งข้อมูลใหม่เพื่อสร้างรายการ
- `PUT` แทนที่ทรัพยากรทั้งชิ้น เรียกซ้ำกี่ครั้งผลก็เหมือนเดิม
- `DELETE` ลบทรัพยากร เรียกซ้ำกี่ครั้งผลก็เหมือนเดิม

ตามนิยามของ RFC 9110 `PUT` และ `DELETE` เป็น idempotent คือทำซ้ำได้โดยผลที่เกิดกับเซิร์ฟเวอร์เหมือนกับทำครั้งเดียว ส่วน `POST` ไม่ได้อยู่ในกลุ่มนี้ การส่ง `POST` ซ้ำอาจสร้างรายการซ้ำได้

รหัสสถานะบอกผลลัพธ์ เช่น `200 OK` สำเร็จ `201 Created` สร้างรายการใหม่สำเร็จ `400` คำขอไม่ถูกต้อง `401` ยังไม่ได้ยืนยันตัวตน `403` ไม่มีสิทธิ์ `404` ไม่พบทรัพยากร และ `500` เซิร์ฟเวอร์ผิดพลาดภายใน


## REST API และ JSON

เซิร์ฟเวอร์จำนวนมากให้บริการ **API** ที่ตอบเป็น **JSON** ซึ่งเป็นข้อความที่มีโครงสร้างด้วยวงเล็บปีกกาสำหรับออบเจกต์และวงเล็บเหลี่ยมสำหรับลิสต์ ตัวอย่าง `[{"name": "ขนมปัง", "price": 15}]` JSON ใช้ `true` `false` และ `null` ตัวพิมพ์เล็กทั้งหมด ซึ่งต่างจากภาษา Python ที่เขียน `True` `False` และ `None`

แนวทาง **REST** จัดทรัพยากรเป็นชื่อ เช่น `/api/items` และใช้เมธอด HTTP เพื่อบอกการกระทำ จึงไม่ต้องตั้งชื่อ `/api/deleteItem` แบบยาว ๆ

## คุกกี้และเซสชัน

HTTP ไม่จำคำขอก่อนหน้า ทุกคำขอเป็นอิสระ เซิร์ฟเวอร์จึงต้องมีวิธีบอกว่าคำขอนี้มาจากผู้ใช้คนเดิม วิธีที่นิยมคือ **คุกกี้** ซึ่งเซิร์ฟเวอร์ส่งผ่านหัวข้อ `Set-Cookie` ให้เบราว์เซอร์เก็บไว้ และเบราว์เซอร์แนบกลับมาทุกคำขอ คุกกี้มักเก็บเพียงรหัสเซสชัน (session id) ส่วนข้อมูลจริงอยู่ที่เซิร์ฟเวอร์

คุกกี้ควรตั้งแอตทริบิวต์ `HttpOnly` เพื่อไม่ให้สคริปต์ฝั่งหน้าเว็บอ่านได้ และ `Secure` เพื่อให้ส่งเฉพาะบนการเชื่อมต่อที่เข้ารหัส (RFC 6265) ไม่ควรเก็บรหัสผ่านหรือข้อมูลส่วนตัวไว้ในคุกกี้แบบข้อความธรรมดา รหัสเซสชันต้องสุ่มให้ยาวและเดายาก ไม่ใช่เลขลำดับ และเซิร์ฟเวอร์ต้องตรวจข้อมูลที่ผู้ใช้ส่งมาทุกครั้ง เพราะการตรวจในเบราว์เซอร์ถูกข้ามได้

## ออกแบบให้ใช้ได้กับทุกจอ

เว็บเดียวกันต้องแสดงผลได้บนมือถือที่กว้าง 360 px และจอคอมพิวเตอร์ที่กว้าง 960 px เทคนิคหลักคือ **media query** ที่เปลี่ยนกฎ CSS ตามความกว้างของหน้าต่าง และการใช้หน่วยสัมพัทธ์เช่น `%` หรือ `rem` แทนค่าตายตัว


## การเข้าถึงได้

คนที่ตาบอดสี ใช้แป้นพิมพ์แทนเมาส์ หรือใช้โปรแกรมอ่านหน้าจอ ต้องใช้เว็บเดียวกันได้ WCAG 2.1 ระดับ AA กำหนดให้ข้อความปกติมี **อัตราส่วนความคมชัด** อย่างน้อย 4.5 ต่อ 1 (เกณฑ์ 1.4.3) อัตราส่วนคำนวณจากความสว่างสัมพัทธ์ของสองสี ตัวอย่างข้อความสีเทาอ่อนบนพื้นขาวไม่ผ่าน แต่สีเทาเข้มผ่านมาก


นอกจากสีแล้ว ควรใช้ปุ่ม `<button>` แทน `<div>` ที่ดักคลิก เพราะปุ่มจริงรับโฟกัสด้วยแป้น Tab และกด Enter ได้ ช่องกรอกทุกช่องต้องมี `<label>` เพื่อให้โปรแกรมอ่านหน้าจอบอกชื่อช่อง และรูปภาพต้องมีคำอธิบายใน `alt`

เครื่องมือตรวจการเข้าถึงได้ในเบราว์เซอร์ช่วยรายงานจุดที่คอนทราสต์ต่ำ ช่องกรอกที่ไม่มีป้าย และรูปที่ไม่มี `alt` เราแก้ตามรายงาน แล้วลองใช้หน้าด้วยแป้น Tab เองอีกครั้ง เพราะเครื่องมืออัตโนมัติจับปัญหาได้ไม่ครบ

## กรอบงานเว็บ

การเขียน HTML CSS และ JavaScript ทั้งหมดเองทุกหน้าเป็นงานมาก กรอบงาน (framework) เช่น React หรือ Vue จัดการการสร้าง DOM และการอัปเดตหน้าให้ตามข้อมูล แนวคิดยังเหมือนเดิม คือแยกข้อมูล การแสดงผล และการคุยกับเซิร์ฟเวอร์ ไม่ว่าจะใช้เครื่องมือใด

## ข้อผิดพลาดที่พบบ่อย

- ใช้ `GET` เพื่อสร้างหรือลบข้อมูล ทำให้ลิงก์หรือการโหลดซ้ำเปลี่ยนข้อมูลโดยไม่ตั้งใจ
- เขียน JSON ด้วย `True` หรือใช้เครื่องหมายคำพูดเดี่ยวแทนคู่ ทำให้ตัวอ่านไม่รับ
- ตั้งสีตัวอักษรและพื้นหลังที่อ่านยาก แล้วคิดว่าเครื่องตัวเองอ่านได้จึงใช้ได้
- เขียนปุ่มด้วย `<div>` แล้วลืมให้รองรับแป้นพิมพ์ ทำให้ผู้ใช้บางกลุ่มกดไม่ได้
