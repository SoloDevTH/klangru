## ถามคนข้างหน้า

มดต่อแถวซื้อข้าวที่โรงอาหาร มองไม่เห็นหัวแถว แต่อยากรู้ว่าตัวเองอยู่ลำดับที่เท่าไร จึงถามคนข้างหน้า คนข้างหน้าก็ไม่รู้ จึงถามต่อไปเรื่อย ๆ จนถึงคนแรกซึ่งตอบได้ทันทีว่า "ฉันที่ 1" คำตอบจึงส่งย้อนกลับมา คนที่สองตอบ 2 คนที่สามตอบ 3 จนถึงมด

วิธีคิดนี้คือ **การเรียกซ้ำ (recursion)** แก้ปัญหาด้วยการแก้ปัญหาแบบเดียวกันที่เล็กลงหนึ่งขั้น บทฟังก์ชันแนะนำ `fact(n)` ไว้แล้ว บทนี้จะไล่ดูว่าโปรแกรมทำงานอย่างไรทีละขั้น ใช้กับข้อมูล และเทียบกับการวนซ้ำ

## สองส่วนที่ขาดไม่ได้

1. **กรณีฐาน (base case)** ตอบได้ทันทีโดยไม่เรียกตัวเอง เหมือนคนแรกในแถว
2. **กรณีเรียกซ้ำ (recursive case)** เรียกตัวเองกับปัญหาที่ **เล็กลง** และเข้าใกล้กรณีฐานทุกครั้ง แล้วนำผลมาประกอบเป็นคำตอบ

```python
def sum_to(n):          # 1 + 2 + ... + n
    if n == 0:          # กรณีฐาน
        return 0
    return n + sum_to(n - 1)   # ปัญหาเล็กลงหนึ่งขั้น

print(sum_to(4))        # 10
```

## ไล่การทำงาน: กองการเรียก

ทุกครั้งที่เรียกฟังก์ชัน Python สร้าง **กรอบ (frame)** ใหม่เก็บตัวแปรของการเรียกครั้งนั้น แล้ววางซ้อนบน **กองการเรียก (call stack)** การเรียกครั้งบนสุดเท่านั้นที่กำลังทำงาน ครั้งที่อยู่ข้างล่างรอผล เมื่อครั้งบนสุด `return` กรอบนั้นถูกยกออก แล้วค่าส่งให้ครั้งที่อยู่ถัดลงไปทำงานต่อจากจุดที่ค้างไว้

`sum_to(4)` จึงมี `n` สี่ตัวที่ไม่ปนกัน (4, 3, 2, 1) และอีกหนึ่งกรอบของ `sum_to(0)` ขาลงมีแต่การเรียก ยังไม่มีการบวก การบวกเกิดในขาขึ้น: 0 → 1 + 0 = 1 → 2 + 1 = 3 → 3 + 3 = 6 → 4 + 6 = 10

ตำแหน่งของคำสั่งเทียบกับการเรียกซ้ำจึงสำคัญ

```python
def countdown(n):
    if n == 0:
        print("ปล่อยจรวด!")
        return
    print(n)             # ทำในขาลง
    countdown(n - 1)
    print("กลับจาก", n)  # ทำในขาขึ้น

countdown(3)
```

ผลคือ `3`, `2`, `1`, `ปล่อยจรวด!` แล้วจึง `กลับจาก 1`, `กลับจาก 2`, `กลับจาก 3` คำสั่งหลังการเรียกซ้ำทำงานย้อนลำดับ เพราะกรอบล่างสุดได้ทำต่อเป็นตัวสุดท้าย

## เรียกซ้ำกับลิสต์และสตริง

ลิสต์และสตริงแบ่งเป็น "ตัวแรก" กับ "ส่วนที่เหลือ" ได้ ส่วนที่เหลือก็เป็นลิสต์หรือสตริงที่สั้นลง

```python
def total(a):
    if len(a) == 0:
        return 0
    return a[0] + total(a[1:])

def is_palindrome(s):    # อ่านกลับหลังได้เหมือนเดิมไหม
    if len(s) <= 1:
        return True
    return s[0] == s[-1] and is_palindrome(s[1:-1])

print(total([4, 7, 1]))          # 12
print(is_palindrome("ยาย"))      # True
print(is_palindrome("racecar"))  # True
```

โครงสร้างที่ซ้อนตัวเอง เช่น โฟลเดอร์ที่มีโฟลเดอร์ย่อย ผังองค์กร หรือแผนภาพต้นไม้ เหมาะกับการเรียกซ้ำเป็นพิเศษ เพราะ "นับไฟล์ในโฟลเดอร์" คือ "นับไฟล์ที่อยู่ตรงนี้ บวกผลนับของแต่ละโฟลเดอร์ย่อย"

## เรียกตัวเองมากกว่าหนึ่งครั้ง

จำนวนฟีโบนัชชี $0, 1, 1, 2, 3, 5, 8, \ldots$ นิยามว่า $F(n) = F(n-1) + F(n-2)$ โดย $F(0) = 0$ และ $F(1) = 1$

```python
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print(fib(6))   # 8
```

การเรียกแต่ละครั้งแตกเป็นสองกิ่ง จึงวาดเป็น **ต้นไม้การเรียก** (ดูภาพ) `fib(4)` เรียกทั้งหมด 9 ครั้ง และ `fib(5)` เรียก 15 ครั้ง เพราะคำนวณค่าเดิมซ้ำหลายรอบ เช่น `fib(2)` ถูกคำนวณสองครั้งใน `fib(4)` และสามครั้งใน `fib(5)` จำนวนการเรียกจึงโตเร็วมากเมื่อ n โตขึ้น แก้ได้ด้วยการจำผลที่เคยคำนวณไว้ หรือเขียนแบบวนซ้ำ

สังเกตว่า **จำนวนการเรียกทั้งหมด** ต่างจาก **ความลึกของกองการเรียก** `fib(5)` เรียก 15 ครั้ง แต่ในขณะใดขณะหนึ่งมีกรอบซ้อนกันอย่างมาก 5 กรอบ (fib(5) → fib(4) → fib(3) → fib(2) → fib(1))

## เรียกซ้ำหรือวนซ้ำ

ทุกปัญหาที่แก้ด้วยการเรียกซ้ำเขียนแบบวนซ้ำได้ และกลับกัน

```python
def sum_to_loop(n):
    s = 0
    for i in range(1, n + 1):
        s = s + i
    return s

print(sum_to_loop(4))   # 10
```

| | การเรียกซ้ำ | การวนซ้ำ |
|---|---|---|
| เหมาะกับ | ปัญหาที่ซ้อนตัวเอง เช่น ต้นไม้ โฟลเดอร์ แบ่งครึ่ง | ทำซ้ำตามลำดับธรรมดา |
| หน่วยความจำ | ใช้หนึ่งกรอบต่อการเรียกที่ค้างอยู่ | ใช้ตัวแปรชุดเดียว |
| ข้อจำกัด | Python จำกัดความลึกไว้ราว 1,000 ชั้น เกินจะเกิด `RecursionError` | ไม่มีข้อจำกัดนี้ |

ดังนั้น `sum_to(5000)` แบบเรียกซ้ำจะเกิด `RecursionError` ส่วนแบบวนซ้ำได้คำตอบปกติ ควรเลือกแบบที่อ่านง่ายและเหมาะกับขนาดข้อมูล

## ข้อผิดพลาดที่พบบ่อย

- **ไม่มีกรณีฐาน** หรือกรณีฐานไม่มีวันถึง เช่น ลดทีละ 2 จากเลขคี่แต่ฐานคือ `n == 0`
- **ปัญหาไม่เล็กลง** เรียก `f(n)` ซ้ำด้วยค่าเดิมหรือ `f(n + 1)`
- **ลืม `return` หน้าการเรียกซ้ำ** ผลที่ได้จากชั้นล่างหายไป ได้ `None`
- **คิดว่าคำสั่งหลังการเรียกซ้ำทำในขาลง** จริง ๆ ทำในขาขึ้นและย้อนลำดับ
- **สับสนจำนวนการเรียกกับความลึก** ต้นไม้การเรียกอาจมีหลายกิ่งแต่ไม่ลึก
