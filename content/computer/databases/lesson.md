## ตารางยืมหนังสือที่ข้อมูลไม่ตรงกัน

ห้องสมุดโรงเรียนบันทึกการยืมในตารางคำนวณแผ่นเดียว ทุกแถวมีชื่อนักเรียน ชั้น ชื่อหนังสือ และวันที่ยืม เมื่อฟ้าย้ายจาก ม.4/1 ไป ม.4/3 บรรณารักษ์ต้องแก้ทุกแถวที่ฟ้าเคยยืม ถ้าแก้ไม่ครบ ระบบจะบอกว่าฟ้าอยู่สองห้องพร้อมกัน ปัญหานี้คือ **ข้อมูลซ้ำซ้อน** ซึ่งแก้ได้ด้วยการออกแบบ **ฐานข้อมูล** ที่ดี บทนี้ต่อจากบทการประมวลผลข้อมูล และใช้ลิสต์กับดิกชันนารีที่เรียนมาแล้ว

## ระบบฐานข้อมูลทำอะไร

**ระบบจัดการฐานข้อมูล (DBMS)** เก็บข้อมูลแยกจากโปรแกรม หลายโปรแกรมและหลายคนใช้ข้อมูลชุดเดียวกันได้พร้อมกัน ตรวจว่าข้อมูลถูกต้องตามกฎที่ตั้งไว้ และทำงานเป็น **ธุรกรรม (transaction)** คือชุดคำสั่งที่ต้องสำเร็จทั้งหมดหรือไม่เกิดเลย เช่น การยืมหนังสือต้องทั้งบันทึกการยืมและลดจำนวนเล่มที่ว่าง ถ้าไฟดับตรงกลาง ระบบจะย้อนกลับทั้งชุด ไม่ค้างครึ่งเดียว

ข้อมูลที่จัดเป็นตารางมีคอลัมน์ชัดเจนเรียกว่า **ข้อมูลมีโครงสร้าง** ส่วนภาพถ่าย คลิปเสียง หรือข้อความแชทเป็น **ข้อมูลไม่มีโครงสร้าง** ซึ่งเก็บและค้นต่างออกไป

## ฐานข้อมูลเชิงสัมพันธ์

**ฐานข้อมูลเชิงสัมพันธ์ (relational database)** เก็บข้อมูลเป็น **ตาราง** แต่ละ **แถว (row)** คือสิ่งหรือเหตุการณ์หนึ่ง เช่น นักเรียนหนึ่งคนหรือการยืมหนึ่งครั้ง แต่ละ **คอลัมน์ (column)** คือคุณสมบัติหนึ่ง เช่น ชื่อ ชั้น ปีที่พิมพ์ และมีชนิดข้อมูลกำหนดไว้

- **คีย์หลัก (primary key)** คือคอลัมน์ที่ค่าไม่ซ้ำและไม่ว่าง ใช้ระบุแถว เช่น รหัสนักเรียน ชื่อใช้ไม่ได้เพราะซ้ำกันได้
- **คีย์นอก (foreign key)** คือคอลัมน์ที่อ้างคีย์หลักของอีกตาราง เช่น `student_id` ในตารางการยืม ฐานข้อมูลตรวจ **ความถูกต้องของการอ้างอิง** ไม่ยอมให้บันทึกการยืมของรหัสนักเรียนที่ไม่มีอยู่จริง

## ออกแบบตารางเพื่อลดข้อมูลซ้ำ

แยกข้อมูลเป็นสามตาราง (ดูภาพ) `students` เก็บนักเรียนคนละแถว `books` เก็บหนังสือเล่มละแถว และ `loans` เก็บการยืมแต่ละครั้ง โดยอ้างนักเรียนและหนังสือด้วยรหัส ชั้นของฟ้าจึงอยู่ที่เดียว แก้ครั้งเดียวก็ถูกทุกที่

ความสัมพันธ์ระหว่างนักเรียนกับการยืมเป็นแบบ **หนึ่งต่อหลาย** นักเรียนหนึ่งคนยืมได้หลายครั้ง ส่วนนักเรียนกับหนังสือเป็นแบบ **หลายต่อหลาย** ซึ่งต้องมีตารางกลางอย่าง `loans` เชื่อมไว้

## สืบค้นด้วย SQL

**SQL** เป็นภาษาที่ใช้สร้างตารางและสืบค้นข้อมูล ตัวอย่างนี้ใช้ SQLite ซึ่งมาพร้อม Python

```python
import sqlite3
con = sqlite3.connect(":memory:")       # ฐานข้อมูลชั่วคราวในหน่วยความจำ
con.executescript("""
CREATE TABLE books (book_id INTEGER PRIMARY KEY, title TEXT,
                    category TEXT, year INTEGER);
INSERT INTO books VALUES (101, 'นิทานดวงดาว', 'นิยาย', 2558),
  (102, 'Python เบื้องต้น', 'คอมพิวเตอร์', 2565),
  (105, 'อัลกอริทึมสนุก', 'คอมพิวเตอร์', 2567);
""")
rows = con.execute("""SELECT title, year FROM books
                      WHERE category = 'คอมพิวเตอร์'
                      ORDER BY year DESC""").fetchall()
print(rows)   # [('อัลกอริทึมสนุก', 2567), ('Python เบื้องต้น', 2565)]
```

- `SELECT` เลือกคอลัมน์ (`*` คือทุกคอลัมน์) `FROM` บอกตาราง
- `WHERE` กรองแถวตามเงื่อนไข ใช้ `=`, `>`, `>=`, `AND`, `OR`
- `ORDER BY` เรียงผล `ASC` น้อยไปมาก (ค่าเริ่มต้น) `DESC` มากไปน้อย
- `COUNT(*)` นับจำนวนแถว

**`JOIN`** รวมแถวจากหลายตารางที่คีย์ตรงกัน เช่น หาว่าใครยืมหนังสือคอมพิวเตอร์

```sql
SELECT students.name, books.title
FROM loans
JOIN students ON loans.student_id = students.student_id
JOIN books ON loans.book_id = books.book_id
WHERE books.category = 'คอมพิวเตอร์';
```

## เก็บในเครื่องหรือบนคลาวด์

ฐานข้อมูลในเครื่อง เช่น ไฟล์ SQLite ใช้ได้แม้อินเทอร์เน็ตล่ม ข้อมูลอยู่ในมือเรา แต่ใช้ร่วมกันหลายที่ยาก และถ้าเครื่องเสียโดยไม่สำรองข้อมูลก็หายหมด ฐานข้อมูลบน **คลาวด์** เข้าถึงจากหลายสาขาได้ ผู้ให้บริการดูแลการสำรอง แต่ต้องมีอินเทอร์เน็ต มีค่าบริการ และต้องเชื่อใจผู้ให้บริการเรื่องความเป็นส่วนตัว การจัดข้อมูลก็มีข้อแลกเปลี่ยนเช่นกัน แยกตารางลดข้อมูลซ้ำแต่ต้อง JOIN ตอนอ่าน

## ความปลอดภัยของข้อมูล

**ความปลอดภัย** คือกันไม่ให้คนที่ไม่มีสิทธิ์อ่านหรือแก้ข้อมูล ส่วน **ความเป็นส่วนตัว** คือการใช้ข้อมูลส่วนบุคคลอย่างเหมาะสมตามที่เจ้าของยินยอม ระบบที่ปลอดภัยอาจยังละเมิดความเป็นส่วนตัวได้ถ้าเก็บข้อมูลเกินจำเป็น

ช่องโหว่ที่พบบ่อยคือ **การแทรกคำสั่ง SQL (SQL injection)** เกิดเมื่อโปรแกรมนำข้อความที่ผู้ใช้พิมพ์ไปต่อเป็นคำสั่ง SQL ตรง ๆ ข้อความที่มีเครื่องหมาย `'` จะเปลี่ยนความหมายของคำสั่งได้ วิธีป้องกันคือ **ใช้ตัวยึดตำแหน่ง** `?` ให้ฐานข้อมูลถือว่าข้อมูลรับเข้าเป็นข้อมูลเสมอ ร่วมกับการตรวจข้อมูลรับเข้า เช่น รหัสนักเรียนต้องเป็นตัวเลข 5 หลัก และให้โปรแกรมมีสิทธิ์เท่าที่จำเป็น

```python
import sqlite3
con = sqlite3.connect(":memory:")
con.execute("CREATE TABLE students (student_id INTEGER PRIMARY KEY, name TEXT)")
con.execute("INSERT INTO students VALUES (1, 'ฟ้า'), (2, 'ต้น')")
name = "ฟ้า"     # ข้อความที่ผู้ใช้พิมพ์มา
# ไม่ปลอดภัย: "SELECT ... WHERE name = '" + name + "'"
rows = con.execute("SELECT student_id FROM students WHERE name = ?",
                   (name,)).fetchall()
print(rows)      # [(1,)]
```

**รหัสผ่านห้ามเก็บเป็นข้อความตรง ๆ** และไม่ควรเข้ารหัสแบบถอดกลับได้ ให้เก็บ **ค่าแฮช** ซึ่งคำนวณทางเดียว ย้อนกลับเป็นรหัสผ่านไม่ได้ ตอนเข้าระบบก็แฮชรหัสที่พิมพ์แล้วเทียบ ต้องเติม **ซอลต์ (salt)** ค่าสุ่มที่ต่างกันในแต่ละบัญชี เพื่อให้รหัสผ่านเหมือนกันได้ค่าแฮชต่างกัน และใช้ฟังก์ชันที่ **ตั้งใจให้ช้า** เช่น bcrypt, scrypt, Argon2 หรือ PBKDF2 ที่วนหลายแสนรอบ ผู้ใช้จริงรอไม่ถึงวินาที แต่ผู้ที่ขโมยฐานข้อมูลไปจะลองเดารหัสได้ช้ามาก

## ข้อผิดพลาดที่พบบ่อย

- **ใช้ชื่อเป็นคีย์หลัก** ชื่อซ้ำกันได้และเปลี่ยนได้
- **เก็บข้อมูลเดียวกันซ้ำหลายตาราง** แก้ไม่ครบแล้วข้อมูลขัดกัน
- **ลืม `WHERE` ในคำสั่งแก้หรือลบ** กระทบทุกแถว
- **JOIN โดยไม่ระบุ `ON`** ได้ทุกคู่ของแถว ผลมากผิดปกติ
- **ต่อข้อความผู้ใช้เข้าคำสั่ง SQL** เปิดช่องให้แทรกคำสั่ง
- **เก็บรหัสผ่านเป็นข้อความหรือแฮชเร็วไม่มีซอลต์**
