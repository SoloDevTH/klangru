## computer.programming.testing-debugging (content/computer/testing-debugging)
- โจทย์ 18 ข้อ (ตัวเลข 6, ตัวเลือก 5, ข้อความ 2, เรียงลำดับ 1, จับคู่ 1, เขียนโค้ด 3) ความยาก 1–5 ครบ

- ไม่แน่ใจ: ค่า "ตรวจประมาณสามครั้ง" ในตัวอย่างการแบ่งครึ่งเป็นตัวอย่างประกอบ ไม่ได้ตรวจกับแหล่งอ้างอิง

## computer.algorithms.design-strategies (content/computer/design-strategies)
- โจทย์ 18 ข้อ (ตัวเลข 8, ตัวเลือก 5, ข้อความ 2, เรียงลำดับ 1, จับคู่ 1, เขียนโค้ด 3) ความยาก 1–5 ครบ (แผนระบุ 6.5 ของหัวข้อ)

- ไม่แน่ใจ: โจทย์ค้นหาคู่ใช้ n = 50000 ในการทดสอบเวลา ควรดูว่าตัวรันในแอปเร็วพอภายในเวลาที่กำหนด
- ภาพ fib-call-tree ต่อ n ในข้อความ มีการเรียก 15 ครั้งตรงกับเฉลยของโจทย์ p008

## computer.security.secure-coding (content/computer/secure-coding)
- โจทย์ 18 ข้อ (ตัวเลข 5, ตัวเลือก 6, ข้อความ 2, เรียงลำดับ 1, จับคู่ 1, เขียนโค้ด 3) ความยาก 1–5 ครบ
- ภาพ 1 ภาพ (SVG): ขอบเขตการไหลของข้อมูลจากผู้ใช้ถึงฐานข้อมูลและหน้าเว็บ

- ไม่แน่ใจ: หัวข้อนี้ไม่ได้ตั้งธง sensitive เพราะไม่อยู่ในหมวดเรื่องอ่อนไหวของคู่มือ ผู้ตรวจอาจต้องยืนยัน

## ผลการตรวจของผู้ตรวจ
- strings-formatting: p007 คู่ของ isdigit แก้เป็นค่า bool `False`; p012 เปลี่ยนความกว้างคอลัมน์เป็น 12/4/10 เพราะโค้ดเดิมตรงกับตัวอย่างในบทเรียน; p017 เปลี่ยนจาก 7 เป็น 42 ไม่ให้ซ้ำบทเรียน
- collections: ตัวอย่างแสดงวิธีทำสองตัวเดิมเป็นเฉลยของ p016 และ p017 ตรงตัว จึงเปลี่ยนเป็นจัดกลุ่มคะแนนตามห้องและหมุนทวนเข็มนาฬิกา; p014 และ p015 เปลี่ยนข้อมูลไม่ให้ซ้ำบทเรียน; กระจายตำแหน่งคำตอบ p004 และ p011
- files-exceptions: p017 เพิ่มแถวที่มีช่องไม่ครบเพื่อให้เกิด TypeError จริง (เดิมค่าว่างเกิด ValueError ไม่ใช่ TypeError ตามคำใบ้) คำตอบเป็น (175, 3); p012 ปรับคำถามให้ตรงตัวเลือก; ลดความยากของ p014 และ p015
- testing-debugging: p018 เปลี่ยนเป็นโจทย์ให้ผู้เรียน **เขียนชุดทดสอบ** `test_is_leap(is_leap)` ซึ่งชุดทดสอบของระบบส่งฟังก์ชันที่ถูกหนึ่งตัวและฟังก์ชันที่มีบั๊กสี่ตัวเข้าไป ทำได้กับชนิดโจทย์ code ปัจจุบัน; เพิ่มตัวอย่าง unittest ในบทเรียน; ภาพแบ่งครึ่งเดิมป้ายถูกตัดและคำบรรยายบอกคำตอบ p008 จึงวาดใหม่และเปลี่ยน p008 เป็น 128 บรรทัด (7 ครั้ง)
- design-strategies: p008 เปลี่ยนเป็น fib(6) = 25 การเรียก เพราะภาพแสดง 15 โหนดของ fib(5); p010 เปลี่ยนเป็นเหรียญ 1, 4, 5 ทอน 8 เพราะเดิมซ้ำตัวอย่างในบทเรียน; เพิ่มหอคอยฮานอย การเลือกกิจกรรม และเป้หลังแบบ 0/1 ในบทเรียนตามขอบเขตแผน; ความยากหัวข้อ 6.5 อยู่ในช่วง 1–10 ของสคีมา ไม่ต้องแก้
- secure-coding: ตัวอย่างแสดงวิธีทำทั้งสองเดิมเป็นเฉลยของ p016 และ p018 จึงเปลี่ยนเป็นรหัสสมาชิก `M[0-9]{6}` และคำสั่งค้นราคาเมนู; แก้ลูกศรในภาพให้ฐานข้อมูลรับข้อมูลจากตรรกะธุรกิจตามคำอธิบายภาพ; เปลี่ยนอ้างอิง "การเข้ารหัส" เป็น Secure coding; กระจายตำแหน่งคำตอบ; ไม่พบวิธีโจมตีที่ใช้งานได้ ชุดทดสอบใช้ข้อความธรรมดาเท่านั้น
