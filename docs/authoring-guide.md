# คู่มือเขียนเนื้อหา

ใช้หัวข้อ `content/math/linear-equations/` เป็นตัวอย่างอ้างอิง กฎทั้งหมดของ schema อยู่ใน `docs/decisions/0004-content-model.md`

## เพิ่มหัวข้อใหม่

1. สร้างโฟลเดอร์ `content/<วิชา>/<ชื่อหัวข้อภาษาอังกฤษ>/`
2. คัดลอก `topic.yaml`, `lesson.md` และ `problems.yaml` จากหัวข้อตัวอย่าง แล้วแก้ไข
3. ตั้ง `id` ใหม่ที่ไม่ซ้ำ และใส่ `prerequisites` ให้ครบ
4. รัน `npm run validate` แก้จนไม่มี error
5. รัน `npm run dev` แล้วเปิดหัวข้อในเบราว์เซอร์ ลองทำโจทย์เองทุกข้อ
6. เปิด Pull Request ให้ผู้ตรวจอีกคนดู

## ชุดเนื้อหาต่อหัวข้อ

- **บทเรียน** 500–900 คำ เรียงเป็น: อธิบายด้วยภาพหรือสถานการณ์จริง → หลักการหรือสูตร → ตัวอย่างพร้อมวิธีทำอย่างน้อย 2 ข้อ → ข้อผิดพลาดที่พบบ่อย
- **คำสำคัญ** 2–4 คำ และ **แฟลชการ์ด** 3–5 ใบ
- **โจทย์** อย่างน้อย 10 ข้อ ความยากอย่างน้อย 3 ระดับ ใช้ชนิดโจทย์อย่างน้อย 3 แบบ มีโจทย์สถานการณ์จริงอย่างน้อย 2 ข้อ

## เขียนโจทย์ให้ดี

- **คำใบ้** ไล่จากกว้างไปเฉพาะ: ข้อแรกชี้ว่าควรคิดเรื่องอะไร ข้อสุดท้ายบอกวิธี แต่ไม่บอกตัวเลขคำตอบ
- **misconception** ให้คิดว่านักเรียนจะผิดแบบไหน แล้วคำนวณ "คำตอบผิด" ที่ความผิดนั้นให้ออกมาจริง ๆ ใส่ไว้พร้อมคำอธิบายว่าผิดตรงไหน
- **ตัวเลือกหลอกใน mcq** ทุกตัวต้องมาจากความผิดที่เกิดขึ้นได้จริง และต้องมี `feedback`
- **หน่วย** ใส่ใน `answer.unit` และบอกในโจทย์ว่าต้องตอบเป็นหน่วยอะไร
- **ทศนิยม** ใส่ `tolerance` เสมอเมื่อคำตอบไม่ใช่จำนวนเต็ม
- **ตรวจคำตอบทุกข้อด้วยการคำนวณจริง** คำตอบผิดในแอปเรียนสร้างความเสียหายมากที่สุด

## สมการ

- ในบรรทัด: `$x^2 + 1$` แยกบรรทัด: `$$\frac{a}{b}$$`
- ใน YAML ที่ใช้เครื่องหมายคำพูดคู่ ต้องเขียน backslash สองตัว: `"$\\frac{1}{2}$"`
- หน่วยในสมการ: `$9.8\,\mathrm{m/s^2}$`
- ในคำตอบชนิด `expression` และสูตรของสื่อโต้ตอบ ให้เขียน `\cdot` หน้าวงเล็บเมื่อหมายถึงการคูณ เช่น `a\cdot(x-h)^2` (ตัวตรวจจะแจ้ง error ถ้าเขียน `a(x-h)` เพราะกำกวมกับฟังก์ชัน) ส่วนผู้เรียนพิมพ์ `a(x-h)` ได้ตามปกติ

## สื่อประกอบ

ใส่ในรายการ `lessons` ของ `topic.yaml` (ดูตัวอย่างใน ADR 0004 และหัวข้อที่มีอยู่)

- `interactive`: กราฟฟังก์ชันพร้อมแถบเลื่อน (`function-plot`), เส้นจำนวน (`number-line`), การรวมเวกเตอร์ (`vector-add`) ใช้ออฟไลน์ได้
- `simulation`: ลิงก์หน้า PhET เช่น `https://phet.colorado.edu/en/simulations/projectile-motion` แอปจะฝังฉบับภาษาไทยให้ (เลือกเฉพาะซิมูเลชัน HTML5 ไม่ใช่ Java/Flash)
- `video`: ใช้เฉพาะวิดีโอที่สัญญาอนุญาตเปิด ใส่ `questions` เพื่อหยุดถามโจทย์จากคลังของหัวข้อ ณ วินาทีที่กำหนด
- `molecule`: ใส่ PubChem CID แล้วรัน `npm run fetch-assets` เก็บไฟล์ 3 มิติไว้ในคลัง
- โจทย์ `hanzi`: เขียนอักษรจีนตามลำดับขีด ใช้ข้อมูลลำดับขีดจาก hanzi-writer-data
- `figure`: ภาพประกอบ ไฟล์อยู่ในโฟลเดอร์ `figures/` ของหัวข้อ (ดูหัวข้อถัดไป) ใส่ในโจทย์ได้ด้วยฟิลด์ `figure:`
- `worked-example`: ตัวอย่างแสดงวิธีทำ มี `problem`, `steps` (2–10 ขั้น แต่ละขั้นมี `text` และ `why` ได้) และ `answer` ผู้เรียนเปิดดูทีละขั้น จึงควรเขียนให้แต่ละขั้นมีงานชิ้นเดียว
- `check`: คำถามชวนคิดแทรกในบทเรียน อ้างรหัสโจทย์ในคลังของหัวข้อเดียวกัน (ไม่นับในระดับความชำนาญ) วางไว้หลังส่วนที่เพิ่งอธิบาย

## ภาพประกอบ

- **แผนภาพที่วาดเอง (SVG)** เหมาะกับรูปเรขาคณิต แผนภาพแรง วงจร กราฟ ผังงาน
  - ใส่ `viewBox`, `width`, `height` และ `<title>` ใช้ `font-family="sans-serif"` ข้อความไทยได้
  - ห้ามมี `<script>` แอตทริบิวต์ `on...` หรือการโหลดไฟล์จากภายนอก ตัวตรวจจะแจ้ง error
  - แอปแสดงภาพบนพื้นขาวทั้งโหมดสว่างและมืด จึงใช้เส้นสีเข้ม ขนาดไม่เกิน 150 KB
  - คำนวณพิกัดให้ถูกตามสัดส่วนจริง (เช่น สามเหลี่ยม 3-4-5 ต้องเป็น 3:4:5) แล้วเปิดดูภาพจริงทุกครั้งก่อน commit
  - ทีมวาดเองไม่ต้องใส่ `credit`/`source`/`license` ภาพใช้ใบอนุญาตของหัวข้อ
- **ภาพจากแหล่งอื่น** (เช่น Wikimedia Commons) ต้องใส่ `credit`, `source` และ `license` ใช้ได้เฉพาะ CC0, สาธารณสมบัติ (PD), CC BY และ CC BY-SA (2.0–4.0) ภาพ NC ใช้ได้เฉพาะหัวข้อที่เป็น NC ภาพถ่ายไม่เกิน 400 KB
- **`alt` บอกสิ่งที่ภาพสื่อ** สำหรับผู้ใช้โปรแกรมอ่านหน้าจอ และผู้ช่วย AI ก็อ่านข้อความนี้แทนการดูภาพ เช่น "สามเหลี่ยมมุมฉาก ABC มุมฉากที่ C ขา a ยาว 3 ขา b ยาว 4" ไม่ใช่ "รูปสามเหลี่ยม"
- **ภาพในโจทย์ต้องไม่เฉลยคำตอบ** เช่น โจทย์ถามว่าด้านใดเป็นด้านตรงข้ามมุมฉาก ภาพต้องไม่มีป้ายบอก

## ใช้ AI ช่วยร่างโจทย์

```bash
npm run draft -- <วิชา>/<โฟลเดอร์> --count=5
```

โจทย์ที่ร่างจะอยู่ใน `content/_drafts/` ตรวจและคำนวณทุกข้อใหม่ แล้วรัน `npm run approve -- <วิชา>/<โฟลเดอร์>` ดู `docs/setup/ai.md`

## แก้ผ่านหน้าเว็บ (สำหรับครูที่ไม่ใช้ Git)

ใช้หน้า `/admin/` (Decap CMS) แก้หัวข้อ บทเรียน และโจทย์ที่มีอยู่ได้ ทุกการแก้ไขเป็น Pull Request ที่ต้องผ่านการตรวจ ดู `docs/setup/cms.md`

## สถานะและ AI

- เนื้อหาใหม่เริ่มที่ `status: draft` เมื่อพร้อมให้ตรวจเปลี่ยนเป็น `review` และเมื่อผู้ตรวจที่ไม่ใช่ผู้เขียนอนุมัติแล้ว ใส่ชื่อใน `reviewed_by` แล้วเปลี่ยนเป็น `published`
- ถ้าใช้ AI ช่วยร่าง ให้ตั้ง `ai_assisted: true` แอปจะแสดงให้ผู้เรียนเห็น และผู้ตรวจต้องตรวจทุกตัวเลข
- เนื้อหาทั้ง 92 หัวข้อในเฟส 0–5 ร่างโดยใช้ AI ช่วย จึงยังเป็น `draft` และต้องผ่านผู้เชี่ยวชาญวิชาก่อนเผยแพร่
