## โน้ตลับที่ต้องผ่านมือหลายคน

มินส่งโน้ตถึงเพื่อนที่นั่งท้ายห้อง โน้ตต้องผ่านมือเพื่อนอีกห้าคน ใครแอบเปิดอ่านก็ได้ ข้อมูลบนอินเทอร์เน็ตก็เหมือนกัน แพ็กเก็ตผ่านเราเตอร์และสายของคนอื่นหลายจุดก่อนถึงปลายทาง วิธีป้องกันไม่ให้คนกลางอ่านออกคือ **การเข้ารหัสลับ (encryption)** บทนี้เรียนรหัสแบบเก่าเพื่อเข้าใจว่าทำไมจึงอ่อนแอ แล้วดูว่าระบบปัจจุบันปกป้องเราอย่างไร

## คำศัพท์พื้นฐาน

- **ข้อความต้นฉบับ (plaintext)** ข้อความที่อ่านได้ เช่น `MEET AT NOON`
- **ข้อความเข้ารหัส (ciphertext)** ข้อความที่แปลงแล้วจนอ่านไม่ออก
- **อัลกอริทึม** วิธีแปลง และ **กุญแจ (key)** ค่าลับที่ใช้กับอัลกอริทึม
- **การถอดรหัส (decryption)** แปลงกลับเป็นข้อความต้นฉบับด้วยกุญแจ

ความปลอดภัยต้องอยู่ที่ **กุญแจ** ไม่ใช่การปิดบังวิธี อัลกอริทึมที่ใช้กันทั่วโลกจึงเปิดเผยให้ทุกคนตรวจสอบได้

## รหัสแบบเลื่อนตัวอักษร

**รหัสซีซาร์** เลื่อนตัวอักษรแต่ละตัวไปข้างหน้า $k$ ตำแหน่ง พอเลยตัว Z ก็วนกลับไปที่ A (ดูภาพหลังบทอ่านนี้) ถ้าให้ A = 0, B = 1, ..., Z = 25

$$C = (P + k) \bmod 26 \qquad P = (C - k) \bmod 26$$

```python
def caesar(text, k):
    result = ""
    for ch in text:
        if "A" <= ch <= "Z":
            n = (ord(ch) - ord("A") + k) % 26
            result = result + chr(n + ord("A"))
        else:
            result = result + ch      # เว้นวรรคและเครื่องหมายคงเดิม
    return result

secret = caesar("MEET AT NOON", 3)
print(secret)                  # PHHW DW QRRQ
print(caesar(secret, -3))      # MEET AT NOON
```

จุดอ่อนคือมีกุญแจที่ใช้ได้เพียง 25 ค่า (เลื่อน 1 ถึง 25) คนที่ดักได้ข้อความจึง **ลองทุกกุญแจ** ไม่กี่วินาทีก็เจอค่าที่ได้ข้อความอ่านรู้เรื่อง จำนวนกุญแจทั้งหมดที่เป็นไปได้เรียกว่า **ปริภูมิกุญแจ (key space)** ยิ่งใหญ่ยิ่งลองทุกค่ายาก

## รหัสแบบแทนที่และการนับความถี่

**รหัสแบบแทนที่** ไม่ได้เลื่อนเท่ากันทุกตัว แต่จับคู่ตัวอักษรแบบสุ่ม เช่น A → Q, B → M, C → X ... จำนวนวิธีจับคู่คือ $26! \approx 4 \times 10^{26}$ แบบ มากเกินกว่าจะลองทุกค่า แต่ยังแพ้ **การนับความถี่** เพราะตัวอักษรแต่ละตัวถูกแทนด้วยตัวเดิมทุกครั้ง ในภาษาอังกฤษตัว E พบบ่อยที่สุด ตัวที่พบบ่อยที่สุดในข้อความเข้ารหัสจึงน่าจะแทน E แล้วไล่เดาต่อจากคำสั้นอย่าง THE ภาษาไทยก็มีตัวอักษรที่ใช้บ่อยเช่นกัน

## เข้ารหัสด้วยบิต: XOR

คอมพิวเตอร์เก็บทุกอย่างเป็นบิต จึงเข้ารหัสได้ด้วยการดำเนินการ **XOR** (ผลเป็น 1 เมื่อสองบิตต่างกัน) ซึ่งมีสมบัติว่า XOR กุญแจเดิมสองครั้งจะได้ค่าเดิมคืน

```
ตัว A          01000001
กุญแจ      XOR 00101101
เข้ารหัส        01101100
กุญแจ      XOR 00101101
ถอดรหัส         01000001   (ได้ A คืน)
```

ถ้ากุญแจเป็นบิตสุ่มยาวเท่าข้อความและใช้เพียงครั้งเดียว (**one-time pad**) จะถอดไม่ได้เลยหากไม่มีกุญแจ แต่การส่งกุญแจยาวขนาดนั้นให้ผู้รับเป็นเรื่องยาก

## กุญแจสมมาตร: กุญแจดอกเดียวกัน

ระบบปัจจุบันอย่าง **AES** ใช้กุญแจ 128 บิตขึ้นไป ผู้ส่งและผู้รับใช้ **กุญแจดอกเดียวกัน** ทั้งเข้ารหัสและถอดรหัส เรียกว่า **การเข้ารหัสแบบกุญแจสมมาตร** ปริภูมิกุญแจมี $2^{128} \approx 3.4 \times 10^{38}$ ค่า ต่อให้ลองได้ล้านล้านค่าต่อวินาที ก็ต้องใช้เวลาราว $10^{19}$ ปี ซึ่งนานกว่าอายุจักรวาลมาก การเข้ารหัสแบบนี้เร็ว แต่มีปัญหาว่า **จะส่งกุญแจให้ผู้รับอย่างปลอดภัยได้อย่างไร** ถ้าส่งไปทางเดียวกับข้อความ คนกลางก็ได้กุญแจด้วย

## กุญแจสาธารณะ: แม่กุญแจที่ใครก็ล็อกได้

**การเข้ารหัสแบบกุญแจสาธารณะ** แก้ปัญหานี้ด้วย **คู่กุญแจ** ที่ต่างกันแต่สัมพันธ์กันทางคณิตศาสตร์ (ดูภาพ)

- **กุญแจสาธารณะ** แจกให้ทุกคน ใช้ **เข้ารหัส** เหมือนแม่กุญแจที่เปิดค้างไว้ ใครก็กดล็อกได้
- **กุญแจส่วนตัว** เจ้าของเก็บไว้คนเดียว ใช้ **ถอดรหัส** เหมือนลูกกุญแจที่เปิดแม่กุญแจนั้นได้

ใครอยากส่งความลับถึงต้นข้าว ก็เข้ารหัสด้วยกุญแจสาธารณะของต้นข้าว แล้วมีแต่ต้นข้าวที่ถอดได้ ใช้กลับทางได้ด้วย คือเจ้าของ **ลงลายมือชื่อดิจิทัล** ด้วยกุญแจส่วนตัว แล้วทุกคนตรวจด้วยกุญแจสาธารณะว่ามาจากเจ้าของจริงและไม่ถูกแก้ แต่วิธีนี้คำนวณช้ากว่าแบบสมมาตรมาก

## HTTPS ใช้ทั้งสองแบบ

เมื่อเปิดเว็บที่ขึ้นต้นด้วย `https://` (ดูภาพ)

1. เซิร์ฟเวอร์ส่ง **ใบรับรอง** ที่มีกุญแจสาธารณะ และลงลายมือชื่อโดยหน่วยงานออกใบรับรองที่เบราว์เซอร์เชื่อถือ
2. เบราว์เซอร์ตรวจว่าใบรับรองถูกต้องและตรงกับชื่อโดเมน
3. ทั้งสองฝ่ายใช้การเข้ารหัสแบบกุญแจสาธารณะตกลง **กุญแจรอบการใช้งาน** ร่วมกันโดยคนกลางไม่รู้
4. ข้อมูลจริงทั้งหมดเข้ารหัสแบบสมมาตรด้วยกุญแจนั้น ซึ่งเร็ว

รูปแม่กุญแจในเบราว์เซอร์บอกว่าข้อมูลถูกเข้ารหัสระหว่างเรากับ **โดเมนนั้น** ไม่ได้บอกว่าเว็บนั้นน่าเชื่อถือ เว็บฟิชชิงก็ใช้ HTTPS ได้ จึงต้องตรวจชื่อโดเมนเสมอ

## ข้อผิดพลาดที่พบบ่อย

- **คิดว่าซ่อนวิธีเข้ารหัสแล้วปลอดภัย** ความปลอดภัยต้องอยู่ที่กุญแจที่ยาวและสุ่ม
- **คิดว่ากุญแจสาธารณะต้องเก็บเป็นความลับ** แจกได้ทุกคน กุญแจส่วนตัวต่างหากที่ต้องเก็บ
- **คิดว่าแม่กุญแจ HTTPS แปลว่าเว็บไม่หลอกลวง** บอกแค่ว่าการส่งข้อมูลถูกเข้ารหัส
- **สับสนการเลื่อนไปข้างหน้ากับถอยหลัง** เข้ารหัสบวก $k$ ถอดรหัสลบ $k$
