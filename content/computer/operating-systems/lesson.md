## ใครแบ่งเครื่องให้ทุกแอป

มายด์เปิดเพลงฟังขณะคุยแชตและดูแผนที่ไปพร้อมกัน โทรศัพท์มีหน่วยประมวลผลไม่กี่แกน หน่วยความจำก้อนเดียว ลำโพงตัวเดียว แต่ทุกแอปทำงานได้โดยไม่แย่งกันจนพัง ผู้ที่แบ่งทรัพยากรให้ทุกแอปคือ **ระบบปฏิบัติการ (operating system, OS)** เช่น Android, iOS, Windows, macOS และ Linux

## ชั้นของซอฟต์แวร์

ระบบคอมพิวเตอร์แบ่งเป็นชั้น (ดูภาพหลังบทอ่านนี้) แต่ละชั้นใช้บริการของชั้นล่างโดยไม่ต้องรู้รายละเอียด

1. **ฮาร์ดแวร์** หน่วยประมวลผล หน่วยความจำ ดิสก์ จอ ลำโพง การ์ดเครือข่าย
2. **ซอฟต์แวร์ระบบ** มีแกนกลางของระบบปฏิบัติการเรียกว่า **เคอร์เนล (kernel)** และ **ไดรเวอร์** ที่คุยกับอุปกรณ์แต่ละรุ่น รวมถึงโปรแกรมอรรถประโยชน์ เช่น ตัวจัดการไฟล์
3. **ซอฟต์แวร์ประยุกต์** แอปที่ผู้ใช้ใช้ทำงาน เช่น เบราว์เซอร์ เกม แอปแชต

ชั้นบนมองชั้นล่างเป็น **นามธรรม (abstraction)** เช่น แอปจดบันทึกสั่งแค่ "บันทึกไฟล์ note.txt" โดยไม่ต้องรู้ว่าดิสก์เป็น SSD หรือฮาร์ดดิสก์ แบ่งเป็นบล็อกอย่างไร ผู้ผลิตแอปจึงเขียนโปรแกรมครั้งเดียวใช้ได้กับเครื่องหลายรุ่น ชั้นยิ่งสูงยิ่งซ่อนรายละเอียดมาก แต่ก็ควบคุมฮาร์ดแวร์โดยตรงได้น้อยลง

## การเรียกใช้บริการของระบบ

แอปไม่ได้แตะฮาร์ดแวร์เอง แต่ส่งคำขอให้เคอร์เนลทำแทน เรียกว่า **การเรียกใช้บริการของระบบ (system call)** เช่น ขอเปิดไฟล์ อ่าน เขียน ขอหน่วยความจำ หรือส่งข้อมูลทางเครือข่าย หน่วยประมวลผลมีสองโหมด **โหมดผู้ใช้** ที่แอปทำงานโดยสิทธิ์จำกัด และ **โหมดเคอร์เนล** ที่สั่งฮาร์ดแวร์ได้ทุกอย่าง การบังคับให้ทุกคำขอผ่านเคอร์เนลทำให้แอปที่ผิดพลาดหรือประสงค์ร้ายทำลายระบบทั้งเครื่องได้ยาก

```python
f = open("note.txt", "w")    # ระบบปฏิบัติการเปิด (หรือสร้าง) ไฟล์ให้
f.write("ส่งงานวันศุกร์")      # ขอให้เขียนข้อมูลลงไฟล์
f.close()
print(open("note.txt").read())   # ส่งงานวันศุกร์
```

## หน้าที่ของระบบปฏิบัติการ

| หน้าที่ | ตัวอย่าง |
|---|---|
| จัดการกระบวนการ | สร้าง หยุด และสลับให้แอปผลัดกันใช้หน่วยประมวลผล |
| จัดการหน่วยความจำ | แบ่งพื้นที่ให้แต่ละแอป ไม่ให้แอปหนึ่งเขียนทับของอีกแอป |
| จัดการอุปกรณ์ | ใช้ไดรเวอร์คุยกับเครื่องพิมพ์ กล้อง ลำโพง และจัดคิวเมื่อหลายแอปใช้พร้อมกัน |
| จัดการไฟล์ | จัดไฟล์เป็นโฟลเดอร์ ตั้งชื่อ ค้นหา และกำหนดสิทธิ์อ่านเขียน |
| จัดการผู้ใช้และความปลอดภัย | บัญชีผู้ใช้ รหัสผ่าน สิทธิ์ของแต่ละบัญชีและแต่ละแอป |
| ส่วนติดต่อผู้ใช้ | หน้าจอกราฟิก (GUI) หรือบรรทัดคำสั่ง (CLI) |

## กระบวนการและสถานะ

**โปรแกรม** คือไฟล์คำสั่งที่เก็บอยู่ในดิสก์ เมื่อสั่งรัน ระบบปฏิบัติการโหลดเข้าหน่วยความจำกลายเป็น **กระบวนการ (process)** โปรแกรมเดียวรันพร้อมกันหลายกระบวนการได้ เช่น เปิดเบราว์เซอร์สองหน้าต่าง กระบวนการเปลี่ยน **สถานะ** ไปมา (ดูภาพ) **พร้อม** (รอคิวใช้หน่วยประมวลผล) **กำลังทำงาน** และ **รอ** (รอข้อมูลจากดิสก์ เครือข่าย หรือการกดปุ่ม) ระบบปฏิบัติการสลับกระบวนการเร็วมากหลายร้อยครั้งต่อวินาที เราจึงรู้สึกว่าทุกแอปทำงานพร้อมกัน

## จัดคิวหน่วยประมวลผล

เมื่อมีหลายกระบวนการพร้อม ระบบปฏิบัติการต้องเลือกว่าใครได้ก่อน วิธีพื้นฐานมีสามแบบ

- **มาก่อนได้ก่อน (FCFS)** ทำตามลำดับที่มาถึงจนเสร็จทีละงาน ง่ายและยุติธรรม แต่งานสั้นอาจต้องรองานยาว
- **งานสั้นที่สุดก่อน (SJF)** เลือกงานที่ใช้เวลาน้อยที่สุดก่อน เวลารอเฉลี่ยน้อยที่สุด แต่ต้องรู้ล่วงหน้าว่างานใช้เวลาเท่าใด และงานยาวอาจรอนาน
- **วนรอบ (Round Robin)** ให้แต่ละงานใช้ได้คราวละ **ควอนตัม** เช่น 2 หน่วยเวลา ถ้ายังไม่เสร็จให้ไปต่อท้ายคิว ทุกงานได้ทำเป็นระยะ จึงตอบสนองผู้ใช้ได้ดี

ประเมินด้วย **เวลารอ** = เวลาที่อยู่ในคิวพร้อม และ **เวลาตลอดงาน** = เวลาเสร็จ − เวลามาถึง

## หน่วยความจำและทรัพยากรอื่น

ระบบปฏิบัติการให้แต่ละกระบวนการมีพื้นที่หน่วยความจำของตัวเอง โดยแบ่งเป็นช่องขนาดเท่ากันเรียกว่า **หน้า (page)** เช่น หน้าละ 4 KB ถ้า RAM ไม่พอ จะย้ายหน้าที่ไม่ได้ใช้ไปพักในดิสก์ (**หน่วยความจำเสมือน**) ทำให้เปิดแอปได้มากขึ้น แต่ถ้าสลับบ่อยเครื่องจะช้ามาก เพราะดิสก์ช้ากว่า RAM หลายเท่า

ทรัพยากรที่ใช้ได้ทีละคน เช่น เครื่องพิมพ์ ต้องมีคิว ถ้ากระบวนการ A ถือเครื่องพิมพ์แล้วรอสแกนเนอร์ ขณะที่ B ถือสแกนเนอร์แล้วรอเครื่องพิมพ์ ทั้งคู่จะรอกันตลอดไป เรียกว่า **ภาวะติดตาย (deadlock)** วิธีป้องกันง่าย ๆ คือให้ทุกกระบวนการขอทรัพยากรตามลำดับเดียวกัน

## ข้อผิดพลาดที่พบบ่อย

- **คิดว่าระบบปฏิบัติการคือหน้าจอ** หน้าจอเป็นแค่ส่วนติดต่อผู้ใช้ งานหลักอยู่ในเคอร์เนลที่มองไม่เห็น
- **สับสนโปรแกรมกับกระบวนการ** โปรแกรมอยู่ในดิสก์ กระบวนการคือโปรแกรมที่กำลังรัน
- **คิดว่าแอปสั่งฮาร์ดแวร์เอง** ทุกคำขอผ่านการเรียกใช้บริการของระบบ
- **คิดว่าคอมพิวเตอร์แกนเดียวทำหลายงานพร้อมกันจริง** มันสลับงานเร็วมากจนดูเหมือนพร้อมกัน
- **คิดเวลารอรวมเวลาที่ตัวเองทำงาน** เวลารอนับเฉพาะเวลาที่อยู่ในคิว
