## ปัญหาเดียวกัน หลายวิธีคิด

ร้านอาหารมีเมนู 10 รายการ และต้องเลือกว่าจะใส่หรือไม่ใส่แต่ละรายการในชุดโปรโมชัน ถ้าลองทุกการเลือกจะมีทางให้ตรวจมากกว่าพันทาง และเมื่อรายการเพิ่มเป็น 30 ทางเลือกจะเกินพันล้านทาง ผู้ออกแบบอัลกอริทึมจึงต้องเลือก **กลยุทธ์** ที่เหมาะกับปัญหา บทนี้จะดูกลยุทธ์หลักสี่แบบ และดูว่าเมื่อไรที่แต่ละแบบให้คำตอบถูกต้อง

## ลองทุกแบบ (brute force)

วิธีนี้ตรวจทุกคำตอบที่เป็นไปได้แล้วเลือกที่ดีที่สุด ให้ผลที่ถูกต้องเสมอ แต่จำนวนทางเลือกมักโตแบบเลขชี้กำลัง เมื่อมี n รายการที่เปิดหรือปิดได้ จะมีทางเลือก 2 ยกกำลัง n แบบ เมื่อ n เพิ่มขึ้นเพียงเล็กน้อยจำนวนจะพุ่งขึ้นอย่างรวดเร็ว จึงใช้เป็นพื้นฐานสำหรับเปรียบเทียบเท่านั้น

## แบ่งแยกและเอาชนะ (divide and conquer)

แบ่งปัญหาใหญ่เป็นปัญหาย่อยที่เล็กลง แก้แต่ละส่วนแล้วรวมผลเข้าด้วยกัน การเรียงแบบผสาน (merge sort) ทำแบบนี้ โดยแบ่งรายการครึ่งหนึ่งจนเหลือหนึ่งตัว แล้วรวมสองส่วนที่เรียงแล้วเข้าด้วยกันโดยเปรียบเทียบหัวของทั้งสอง

การค้นหาแบบทวิภาค (binary search) ก็อยู่ในกลุ่มนี้ ในรายการที่เรียงแล้ว ตรวจค่ากลาง ถ้าเป้าหมายอยู่ซ้ายก็ค้นเฉพาะครึ่งซ้าย ถ้าอยู่ขวาก็ค้นครึ่งขวา ทุกครั้งที่ตรวจปัญหาจะเล็กลงครึ่งหนึ่ง

หอคอยฮานอยก็แก้ด้วยวิธีนี้ การย้ายจาน n ใบ ให้ย้าย n − 1 ใบบนไปพักที่หลักกลางก่อน ย้ายจานใบใหญ่สุดไปหลักปลายทาง แล้วย้าย n − 1 ใบกลับมาวางทับ จำนวนครั้งที่ย้ายจึงเป็นไปตาม T(n) = 2T(n − 1) + 1 ซึ่งเท่ากับ 2 ยกกำลัง n ลบ 1

```python
def binary_search(items, target, lo=0, hi=None):
    if hi is None:
        hi = len(items) - 1
    if lo > hi:
        return -1
    mid = (lo + hi) // 2
    if items[mid] == target:
        return mid
    if items[mid] < target:
        return binary_search(items, target, mid + 1, hi)
    return binary_search(items, target, lo, mid - 1)
```

ความสัมพันธ์เวียนเกิด (recurrence) ใช้อธิบายเวลาของอัลกอริทึมแบบแบ่งแยก เช่น merge sort ใช้เวลาประมาณ n log n ส่วนค้นหาแบบทวิภาคทำงานราว log n ครั้ง

## อัลกอริทึมละโมบ (greedy)

ละโมบเลือกทางที่ดูดีที่สุดในขั้นนั้นทุกครั้ง โดยไม่ย้อนกลับมาแก้การเลือกก่อนหน้า เช่น การทอนเงินด้วยเหรียญที่ใหญ่ที่สุดที่ไม่เกินเงินที่เหลือ ซึ่งให้จำนวนเหรียญน้อยที่สุดสำหรับเหรียญบาทของไทย (1, 2, 5, 10) และการเลือกกิจกรรมให้ได้มากที่สุดในห้องเดียว โดยหยิบกิจกรรมที่จบเร็วที่สุดก่อนเสมอ แต่ละโมบไม่ได้ผลถูกกับทุกปัญหา

ถ้ามีเหรียญ 1, 3 และ 4 บาท และต้องทอนเงิน 6 บาท ละโมบจะเลือก 4 ก่อน แล้วเหลือ 2 ซึ่งต้องใช้เหรียญ 1 สองเหรียญ รวม 3 เหรียญ แต่ถ้าใช้ 3 สองเหรียญจะได้เพียง 2 เหรียญ ตัวอย่างนี้แสดงว่าก่อนใช้ละโมบ ต้องพิสูจน์หรือหาตัวอย่างค้านให้ได้ก่อน

## กำหนดการพลวัต (dynamic programming)

ปัญหาที่แบ่งเป็นปัญหาย่อยซ้ำ ๆ จะคำนวณค่าย่อยเดิมซ้ำมาก ฟิบอนัชชีแบบเรียกซ้ำ `fib(n) = fib(n-1) + fib(n-2)` คำนวณค่าย่อยเดิมซ้ำหลายรอบ และจำนวนการเรียกเพิ่มแบบเลขชี้กำลังตาม n วิธีแก้มีสองแบบ

- **การจำค่า (memoization)** เก็บผลที่คำนวณแล้วไว้ในดิกชันนารี และเรียกใช้ซ้ำเมื่อพบอีก
- **ตาราง (tabulation)** คำนวณจากค่าเล็กไปใหญ่แล้วเก็บในลิสต์ ไม่ต้องใช้การเรียกซ้ำ

```python
def fib(n):
    table = [0, 1]
    for i in range(2, n + 1):
        table.append(table[i - 1] + table[i - 2])
    return table[n]
```

การทอนเงินด้วยเหรียญน้อยที่สุดในระบบที่เหรียญไม่ใช่แบบละโมบได้ ต้องใช้ตารางว่า ค่าต่ำสุดของการทอนเงินจำนวนแต่ละค่าคืออะไร โดยอิงจากค่าที่เล็กกว่า

ปัญหาเป้หลังแบบ 0/1 ก็ใช้วิธีเดียวกัน เป้รับน้ำหนักได้ 4 กิโลกรัม มีของ A หนัก 3 กิโลกรัมมูลค่า 45 บาท และของ B กับ C หนักชิ้นละ 2 กิโลกรัมมูลค่าชิ้นละ 28 บาท ละโมบที่เลือกของที่มูลค่าต่อกิโลกรัมสูงสุดก่อนจะหยิบ A แล้วใส่อะไรเพิ่มไม่ได้ ได้ 45 บาท แต่การเลือก B กับ C ได้ 56 บาท กำหนดการพลวัตสร้างตารางว่า ถ้าพิจารณาของ i ชิ้นแรกและน้ำหนักไม่เกิน w จะได้มูลค่าสูงสุดเท่าใด จึงได้คำตอบที่ถูกเสมอ

## การย้อนรอย (backtracking)

ลองเลือกทางหนึ่ง ถ้าพบทางตันก็ถอยกลับแล้วลองทางอื่น เหมาะกับการหาคำตอบที่เป็นไปตามเงื่อนไขหลายข้อ เช่น จัดตำแหน่งที่ไม่ชนกัน การย้อนรอยมักเป็นการลองทุกแบบที่ตัดทางตันทิ้งเร็วขึ้น

## วนซ้ำหรือเรียกซ้ำ

การเรียกซ้ำสะท้อนโครงสร้างของปัญหาได้ชัด แต่แต่ละการเรียกใช้หน่วยความจำและเวลาเพิ่ม ถ้าไม่จำค่าย่อย การเรียกซ้ำอาจช้ากว่าการวนซ้ำมาก การเรียกซ้ำจึงต้องมีเงื่อนไขหยุดที่ชัดเจนเสมอ

## เลือกโครงสร้างข้อมูลให้ลดงาน

บางครั้งการเปลี่ยนโครงสร้างข้อมูลเปลี่ยนความเร็วได้มาก เช่น ตรวจว่ามีคู่ของค่าที่รวมกันได้เป้าหมายหรือไม่ ถ้าเทียบทุกคู่จะใช้เวลาประมาณ n ยกกำลังสอง แต่ถ้าเก็บค่าที่เห็นแล้วไว้ในเซต ตรวจแต่ละค่าด้วยการค้นหาเฉลี่ยเร็ว ทำให้รวมแล้วได้เวลาประมาณ n

## ข้อผิดพลาดที่พบบ่อย

- เลือกละโมบโดยไม่ตรวจกับตัวอย่างค้าน แล้วคิดว่าผลถูกเสมอ
- เขียนการเรียกซ้ำที่ไม่มีเงื่อนไขหยุด
- คำนวณค่าย่อยเดิมซ้ำ ทั้งที่จำค่าไว้ได้
- ใช้ลิสต์ตรวจการมีอยู่ซ้ำ ๆ ในลูปใหญ่ ทำให้ช้าโดยไม่จำเป็น
