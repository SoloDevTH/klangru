## หาชื่อหนึ่งในพันสองร้อยชื่อ

ห้องทะเบียนมีรายชื่อนักเรียน 1,200 คน ถ้ารายชื่อไม่ได้เรียง ต้องไล่ดูทีละชื่อ อาจต้องดูครบทั้ง 1,200 ชื่อ แต่ถ้าเรียงตามตัวอักษรแล้ว เปิดตรงกลาง ดูว่าชื่อที่หาอยู่ครึ่งหน้าหรือครึ่งหลัง แล้วตัดอีกครึ่งทิ้ง ทำซ้ำไม่เกิน 11 ครั้งก็เจอ บทนี้เปรียบเทียบอัลกอริทึมที่ใช้ค้นหาและเรียงลำดับ และวัดว่าแบบใดดีกว่ากันด้วยการนับขั้น ต่อจากบทลิสต์ ดิกชันนารี และการประมวลผลข้อความ

## ค้นหาแบบลำดับ

**การค้นหาแบบลำดับ (linear search)** เทียบทีละตัวตั้งแต่ตัวแรก เป็นวิธี **ลองทุกทาง (brute force)** ที่ง่ายและใช้กับลิสต์ที่ไม่ได้เรียงได้

```python
def linear_search(a, target):
    for i in range(len(a)):
        if a[i] == target:
            return i          # เจอแล้ว หยุดทันที
    return -1                 # ไม่เจอ

print(linear_search([7, 3, 9, 4], 9))   # 2
```

กรณีแย่ที่สุด (ไม่เจอหรืออยู่ท้ายสุด) ต้องเทียบ $n$ ครั้ง เมื่อข้อมูลเพิ่มเป็นสองเท่า จำนวนครั้งก็เพิ่มเป็นสองเท่า

## ค้นหาแบบทวิภาค

**การค้นหาแบบทวิภาค (binary search)** ใช้ได้เฉพาะลิสต์ที่ **เรียงแล้ว** ดูตัวกลาง ถ้าน้อยกว่าเป้าหมายตัดครึ่งซ้ายทิ้ง ถ้ามากกว่าตัดครึ่งขวาทิ้ง (ดูภาพ)

```python
def binary_search(a, target):
    low, high = 0, len(a) - 1
    while low <= high:
        mid = (low + high) // 2
        if a[mid] == target:
            return mid
        elif a[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

print(binary_search([2, 5, 8, 12, 16, 23, 38], 23))   # 5
```

ทุกรอบช่วงที่เหลือหดลงครึ่งหนึ่ง จำนวนครั้งที่เทียบมากที่สุดคือ $\lfloor \log_2 n \rfloor + 1$ ข้อมูล 1,200 ตัวเทียบไม่เกิน 11 ครั้ง ข้อมูลล้านตัวไม่เกิน 20 ครั้ง วิธีนี้เป็นกลยุทธ์ **แบ่งแยกและเอาชนะ (divide and conquer)** คือแบ่งปัญหาให้เล็กลงแล้วแก้ส่วนที่เล็กลง

## เรียงลำดับสามวิธี

**การเรียงแบบเลือก (selection sort)** รอบที่ 1 หาตัวที่น้อยที่สุดแล้วสลับไปไว้ตำแหน่งแรก รอบที่ 2 หาตัวน้อยที่สุดในส่วนที่เหลือไว้ตำแหน่งที่สอง ทำต่อไปเรื่อย ๆ จำนวนครั้งที่เทียบคือ $(n-1) + (n-2) + \cdots + 1 = \frac{n(n-1)}{2}$ เสมอ แม้ข้อมูลจะเรียงอยู่แล้ว

```python
def selection_sort(a):
    for i in range(len(a) - 1):
        m = i
        for j in range(i + 1, len(a)):
            if a[j] < a[m]:
                m = j
        a[i], a[m] = a[m], a[i]    # สลับตัวน้อยสุดมาไว้ที่ i
    return a

print(selection_sort([29, 10, 14, 37, 13]))   # [10, 13, 14, 29, 37]
```

**การเรียงแบบแทรก (insertion sort)** หยิบทีละตัวไปแทรกในส่วนด้านซ้ายที่เรียงแล้ว เหมือนจัดไพ่ในมือ ถ้าข้อมูลเกือบเรียงอยู่แล้วจะเทียบน้อยมาก แต่ถ้าเรียงกลับด้านจะเทียบ $\frac{n(n-1)}{2}$ ครั้งเท่าแบบเลือก

**การเรียงแบบผสาน (merge sort)** ใช้แบ่งแยกและเอาชนะ แบ่งลิสต์ครึ่งหนึ่งไปเรื่อย ๆ จนเหลือตัวเดียว แล้ว **ผสาน** ลิสต์ย่อยที่เรียงแล้วสองลิสต์ โดยเทียบตัวหน้าสุดของทั้งคู่แล้วหยิบตัวที่น้อยกว่า (ดูภาพ) มีการแบ่งราว $\log_2 n$ ชั้น แต่ละชั้นผสานรวมราว $n$ ขั้น จึงใช้ราว $n \log_2 n$ ขั้น

```python
def merge_sort(a):
    if len(a) <= 1:
        return a
    mid = len(a) // 2
    left = merge_sort(a[:mid])
    right = merge_sort(a[mid:])
    out = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            out.append(left[i]); i = i + 1
        else:
            out.append(right[j]); j = j + 1
    return out + left[i:] + right[j:]

print(merge_sort([5, 2, 8, 6, 1, 9, 3, 7]))   # [1, 2, 3, 5, 6, 7, 8, 9]
```

## นับขั้นและสัญกรณ์บิ๊กโอ

เวลาที่วัดด้วยนาฬิกาขึ้นกับเครื่อง จึงเปรียบเทียบอัลกอริทึมด้วย **การนับขั้น** เช่น จำนวนครั้งที่เทียบ และดูว่าโตอย่างไรเมื่อ $n$ ใหญ่ขึ้น เขียนด้วย **สัญกรณ์บิ๊กโอ (Big-O)** ซึ่งเก็บเฉพาะพจน์ที่โตเร็วที่สุดและไม่สนตัวคูณคงที่ (ดูภาพกราฟ)

| บิ๊กโอ | ตัวอย่าง | ขั้นโดยประมาณเมื่อ n = 1,000 |
|---|---|---|
| $O(\log n)$ | ค้นหาแบบทวิภาค | 10 |
| $O(n)$ | ค้นหาแบบลำดับ | 1,000 |
| $O(n \log n)$ | เรียงแบบผสาน | 10,000 |
| $O(n^2)$ | เรียงแบบเลือก แบบแทรก (กรณีแย่) | 1,000,000 |

ตรวจด้วยการทดลองได้ เช่น ถ้าเรียงแบบเลือก 2,000 ตัวใช้ 0.8 วินาที เมื่อข้อมูลเพิ่มเป็น 4 เท่า เวลาจะเพิ่มราว $4^2 = 16$ เท่า ส่วนปัญหาที่ต้องลองทุกทางแบบโตเป็นเลขชี้กำลัง เช่น ลองรหัส $n$ บิตทุกแบบ $2^n$ แบบ จะช้าเกินใช้ได้จริงเมื่อ $n$ ใหญ่

## เลือกโดยชั่งความอ่านง่ายกับประสิทธิภาพ

ไม่มีอัลกอริทึมที่ดีที่สุดเสมอ

- ข้อมูลไม่กี่สิบตัวหรือค้นครั้งเดียว ค้นหาแบบลำดับก็พอ โค้ดสั้นและอ่านง่าย
- ค้นหาบ่อยในข้อมูลมาก คุ้มที่จะเรียงครั้งเดียวแล้วใช้ทวิภาค หรือเก็บในเซตและดิกชันนารี
- ข้อมูลเกือบเรียงอยู่แล้ว แบบแทรกเร็วมาก
- งานจริงใน Python ใช้ `sorted()` หรือ `in` ที่มีมาให้ ซึ่งผ่านการปรับให้เร็วและทดสอบมาแล้ว

โครงสร้างควบคุมก็ต้องเลือกเหตุผลเดียวกัน `for` ที่ `return` ทันทีเมื่อเจอ ทำงานเร็วกว่าการวนครบทุกตัวแล้วจึงตรวจผล ส่วน `while` เหมาะกับทวิภาคเพราะไม่รู้ล่วงหน้าว่าจะวนกี่รอบ ควรอธิบายได้ว่าเลือกเพราะอะไร และเสียอะไรไป

## ข้อผิดพลาดที่พบบ่อย

- **ใช้ทวิภาคกับลิสต์ที่ยังไม่เรียง** ได้คำตอบผิดโดยไม่มีข้อผิดพลาดเตือน
- **กำหนด `low` `high` ผิด** เช่น `high = len(a)` ทำให้ดัชนีเกิน หรือ `low = mid` ทำให้วนไม่จบ
- **ลืมว่าการเรียงก็มีต้นทุน** ค้นครั้งเดียวไม่คุ้มที่จะเรียงก่อน
- **เทียบอัลกอริทึมด้วยข้อมูลไม่กี่ตัว** ความต่างจะเห็นชัดเมื่อ $n$ ใหญ่
- **คิดว่า $O(n^2)$ แปลว่าใช้ $n^2$ วินาทีพอดี** บิ๊กโอบอกอัตราการโต ไม่ใช่เวลาจริง
