# ADR 0004: โครงข้อมูลเนื้อหา ลำดับการเรียน และระดับความชำนาญ (schema v1)

- สถานะ: ยอมรับแล้ว (v1 ทดสอบด้วยหัวข้อจริง 10 หัวข้อ, ปรับเป็น v2 ในเฟส 1–3 ดูส่วนท้าย)
- วันที่: 23 ต.ค. 2569
- ไฟล์อ้างอิง: `packages/schema/src/index.ts`

## โครงโฟลเดอร์

```
content/
  subjects.yaml                 รายชื่อวิชา สี และคำอธิบาย
  <วิชา>/<หัวข้อ>/topic.yaml     ข้อมูลหัวข้อ + รายการบล็อกบทเรียน
  <วิชา>/<หัวข้อ>/lesson.md      คำอธิบาย (Markdown + KaTeX)
  <วิชา>/<หัวข้อ>/problems.yaml  คลังโจทย์ของหัวข้อ (แยกจากบทเรียน)
```

## หัวข้อ (Topic)

หัวข้อเป็นโหนดในกราฟความรู้ ฟิลด์สำคัญมีดังนี้

- `id`: รูปแบบ `วิชา.สาขา.ชื่อ` ห้ามเปลี่ยนหลังเผยแพร่ เพราะความคืบหน้าของผู้เรียนผูกกับรหัสนี้
- `difficulty` (1–10): ใช้ตัดสินลำดับเมื่อหลายหัวข้อเรียนได้พร้อมกัน
- `prerequisites`: หัวข้อที่ต้องรู้ก่อน ข้ามวิชาได้ ห้ามวนลูป
- `encompasses`: ฝึกหัวข้อนี้ถือเป็นการทบทวนหัวข้อพื้นฐานบางส่วน (`weight` 0–1) ตามแนว Math Academy เก็บข้อมูลไว้ตั้งแต่ตอนนี้ แต่จะเริ่มใช้คำนวณในเฟส 3
- `curriculum_tags`: รหัสตัวชี้วัดของหลักสูตรไทย ใช้ค้นหาเท่านั้น **ไม่ใช้จัดลำดับ**
- `lessons`: บล็อก `explanation` (ไฟล์ .md), `video`, `simulation`
- `status`: `draft` → `review` → `published` โดย `published` ต้องมี `reviewed_by`
- `license`, `adapted_from`, `authors`, `ai_assisted`: ดู ADR 0001

## โจทย์ (Problem)

- ชนิดโจทย์ใน v1: `mcq`, `numeric`, `text`, `order`, `match` (`expression` สำหรับตรวจสมการเชิงสัญลักษณ์จะเพิ่มในเฟส 3)
- `difficulty` 1–5: ค่าเริ่มต้นจากผู้เขียน เฟส 2 จะปรับจากสถิติการตอบจริง
- `hints`: 1–4 ขั้น ไล่จากกว้างไปเฉพาะ ขั้นสุดท้ายบอกวิธีแต่ไม่บอกคำตอบ
- `misconceptions`: คำตอบผิดที่พบบ่อยพร้อม feedback เฉพาะ
  - numeric: ตรงกันเมื่อ |คำตอบ − match| ≤ max(tolerance, 0.01)
  - text: เทียบหลังตัดช่องว่างและไม่สนตัวพิมพ์เล็กใหญ่
  - mcq: ใส่ `feedback` ที่ตัวเลือกผิดแต่ละตัวแทน
- `solution`: วิธีทำเต็ม แสดงเมื่อตอบถูก หรือเมื่อผู้เรียนกดดูเฉลย

## สิ่งที่ตัวตรวจ (`npm run validate`) บังคับ

| ระดับ | กฎ |
|---|---|
| error | schema ไม่ผ่าน, YAML ผิดรูปแบบ, รหัสหัวข้อหรือโจทย์ซ้ำ, prerequisite/encompasses อ้างหัวข้อที่ไม่มี, กราฟวนลูป, ไฟล์บทเรียนหาย, สมการ KaTeX เรนเดอร์ไม่ได้, mcq ไม่มีตัวเลือกถูก (หรือถูกหลายตัวโดยไม่ได้ตั้ง `multiple`), misconception ตรงกับคำตอบที่ถูก, ใบอนุญาตไม่เข้ากับต้นฉบับ, `published` ไม่มีผู้ตรวจ |
| warning | โจทย์น้อยกว่า 5 ข้อ, ความยากน้อยกว่า 3 ระดับ, ไฟล์ .md ที่ไม่ได้ถูกอ้าง, encompasses ที่ไม่ใช่บรรพบุรุษในกราฟ |

`npm run validate -- --strict` ถือว่า warning เป็น error ด้วย ใช้ก่อนเปลี่ยนสถานะเป็น `published`

## ลำดับการเรียน

`build` เรียงหัวข้อแบบ topological sort: หัวข้อมาหลัง prerequisite ทั้งหมดเสมอ ถ้าหลายหัวข้อพร้อมกัน ให้ `difficulty` ต่ำกว่ามาก่อน แล้วตามด้วย `id` ผลลัพธ์อยู่ในฟิลด์ `order` ของ `dist/content/index.json` ส่วน `depth` (ความยาวเส้นทาง prerequisite ที่ยาวที่สุด) ใช้วางคอลัมน์ในแผนที่ความรู้

## ระดับความชำนาญ (prototype)

ระดับแบ่งเป็น 4 ขั้นแบบ Khan Academy: 0 ยังไม่เริ่ม · 1 คุ้นเคย · 2 ชำนาญ · 3 เชี่ยวชาญ

"ถูกตั้งแต่ครั้งแรก" หมายถึงตรวจครั้งแรกแล้วถูก และไม่ได้เปิดเฉลยก่อน

| รอบ | เงื่อนไข | ผล |
|---|---|---|
| ฝึก (ทุกข้อของหัวข้อ) | ถูกตั้งแต่ครั้งแรก ≥ 85% และใช้คำใบ้ ≤ 1 ครั้ง | อย่างน้อย "ชำนาญ" |
| ฝึก | ถูก ≥ 60% | อย่างน้อย "คุ้นเคย" |
| ฝึก | ถูก < 60% ขณะอยู่ระดับ "ชำนาญ" ขึ้นไป | ลดลง 1 ระดับ |
| ทบทวน (สุ่ม 3 ข้อ) | ถูกทั้งหมด ขณะอยู่ระดับ "ชำนาญ" ขึ้นไป | "เชี่ยวชาญ" |
| ทบทวน | ถูก < 60% | ลดลง 1 ระดับ (ต่ำสุด "คุ้นเคย") |

**การปลดล็อก:** หัวข้อจะ "พร้อมเรียน" เมื่อ prerequisite ทุกตัวอยู่ระดับ "คุ้นเคย" ขึ้นไป หัวข้อที่ยังขาดพื้นฐานยังเปิดดูได้ แผนที่แค่แสดงเป็นเส้นประ

**ตารางทบทวน (FSRS):** ทุกรอบทั้งฝึกและทบทวนส่งคะแนนให้ ts-fsrs (ปิดช่วงสั้นระดับนาที ตั้งเป้าการจำไว้ 90%)

| ผลของรอบ | คะแนน FSRS |
|---|---|
| ถูก < 60% | Again |
| ถูก < 85% | Hard |
| ถูก 100% และไม่ใช้คำใบ้ | Easy |
| กรณีอื่น | Good |

ค่าตัวเลขเหล่านี้เป็นค่าตั้งต้นสำหรับ prototype ให้ปรับจากผลทดสอบกับผู้เรียน (ดู `docs/phase0/usability-test.md`)

## v2 (เฟส 1–3): สิ่งที่เปลี่ยนจาก v1

### ชนิดโจทย์และบล็อกบทเรียนใหม่

- `expression`: ผู้เรียนกรอกสมการด้วย MathLive ตรวจด้วย Compute Engine โดยแทนค่าตัวแปร 8 จุด เทียบความต่างสัมพัทธ์ ≤ 1e-6 (ต้องได้ค่าที่ใช้ได้อย่างน้อย 3 จุด)
  - `prefix` เช่น `h =` ถ้าผู้เรียนพิมพ์ `h =` มาเองจะถูกตัดออก
  - `expanded: true` ห้ามมีวงเล็บ / `factored: true` ต้องเป็นผลคูณที่มีตัวประกอบเป็นผลบวก
  - คำตอบของผู้เรียนที่เขียน `m(x+1)` ถือเป็นการคูณ (แทรก `\cdot` ให้อัตโนมัติ) ส่วนในไฟล์เนื้อหาตัวตรวจบังคับให้เขียน `m\cdot(x+1)` เพื่อไม่ให้กำกวมกับฟังก์ชัน
  - ทุกการเรียก Compute Engine อยู่ใน scope แยก เพื่อไม่ให้การตีความ `a(...)` เป็นฟังก์ชันค้างไปถึงนิพจน์ถัดไป
- `hanzi`: เขียนอักษรจีนตามลำดับขีด (Hanzi Writer) ผ่านเมื่อผิดไม่เกิน `max_mistakes` ขีด
- บล็อกบทเรียนใหม่: `interactive` (JSXGraph: กราฟพร้อมแถบเลื่อน เส้นจำนวน เวกเตอร์), `molecule` (3Dmol + ไฟล์ SDF จาก PubChem ที่เก็บในคลัง), `simulation` แบบฝัง (PhET ภาษาไทย), `video` ที่หยุดถามโจทย์ตามวินาทีที่กำหนด
- ขั้นต่ำต่อหัวข้อ: โจทย์ 10 ข้อ และความยากอย่างน้อย 3 ระดับ (warning, `--strict` ถือเป็น error)

### ระดับความชำนาญ v2

**รอบฝึกแบบปรับตามผู้เรียน (BKT)** ใช้กับผู้เรียนกลุ่ม `adaptive` ของการทดลอง A/B

- ค่าตั้งต้น: P(รู้แล้ว) 0.25, P(เรียนรู้ต่อข้อ) 0.15, P(พลาด) 0.1, P(เดา) ตามชนิดโจทย์ (ปรนัย 1/จำนวนตัวเลือก ไม่เกิน 0.5, จับคู่/เรียงลำดับ 0.08, ชนิดที่ต้องพิมพ์ 0.03)
- เลือกข้อถัดไปที่ความยากใกล้ระดับเป้าหมายซึ่งคำนวณจาก P(รู้แล้ว)
- จบรอบเมื่อ P(รู้แล้ว) ≥ 0.95 และทำแล้วอย่างน้อย 4 ข้อ หรือครบ 10 ข้อ
- ได้ "ชำนาญ" เมื่อ P(รู้แล้ว) ≥ 0.95 และถูกตั้งแต่ครั้งแรกอย่างน้อย 4 ข้อ

กลุ่ม `fixed` ใช้กฎสัดส่วนเดิมของ v1 (ทุกข้อ, ≥85% และคำใบ้ ≤ 1 → ชำนาญ)

**ทบทวนทางอ้อม (encompasses):** จบรอบฝึกหัวข้อที่ได้ผลดี ระบบให้คะแนนทบทวนแก่หัวข้อพื้นฐานที่ระบุใน `encompasses` ตามน้ำหนัก ทำให้ไม่ต้องทบทวนหัวข้อพื้นฐานซ้ำ (แนวทางย่อของ FIRe จาก Math Academy)

**วัดระดับ (placement):** ทดสอบไล่ตามกราฟ ข้ามหัวข้อที่ตอบถูก และตั้งระดับ "คุ้นเคย" หรือ "ชำนาญ" ให้หัวข้อที่ผ่าน (บันทึก `placed`)

**แฟลชการ์ด:** เข้าคิว FSRS รายใบ (เปิดช่วงสั้นระดับนาที) วันละไม่เกิน 10 ใบใหม่ ส่วนการทบทวนรายหัวข้อยังปิดช่วงสั้นเหมือนเดิม

### ค่าความยากจากข้อมูลจริง

`npm run calibrate -- --stats=stats.json` อ่านผลจากฟังก์ชัน `problem_stats()` ใน Supabase (นับเฉพาะโจทย์ที่มีผู้ทำ ≥ 30 คน) แปลงสัดส่วนถูกครั้งแรก p เป็นค่า Rasch b = ln((1−p)/p) และเสนอระดับใหม่ (p ≥ .85 → 1, ≥ .70 → 2, ≥ .50 → 3, ≥ .30 → 4, ต่ำกว่านั้น → 5) ใส่ `--write` เพื่อเขียนลงไฟล์โดยคงคอมเมนต์เดิม แล้วเปิด PR ให้ผู้ตรวจดู
