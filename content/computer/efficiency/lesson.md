## โปรแกรมสองชิ้นที่ผ่านการทดสอบเหมือนกัน

ฝ่ายทะเบียนให้นักเรียนสองคนเขียนฟังก์ชันตรวจว่ามีรหัสนักเรียนซ้ำในรายชื่อหรือไม่ ทั้งสองโปรแกรมผ่านกรณีทดสอบทุกข้อ แต่กับรายชื่อ 30,000 คน โปรแกรมหนึ่งเสร็จทันที อีกโปรแกรมใช้เวลาหลายนาที แต่โปรแกรมที่เร็วกว่าเขียนซับซ้อนจนครูตรวจไม่ได้ว่าถูกทุกกรณีหรือไม่ การประเมินอัลกอริทึมจึงต้องดูสามด้าน คือ **ประสิทธิภาพ** **ความถูกต้อง** และ **ความชัดเจน** บท [การค้นหาและการเรียงลำดับ](/topic/computer.algorithms.searching-sorting/) ได้นับขั้นและรู้จักบิ๊กโออย่างคร่าว ๆ แล้ว บทนี้นิยามบิ๊กโอให้แม่นยำ และพิสูจน์ว่าวงวนทำงานถูกต้อง

## นับขั้นเป็นฟังก์ชันของ n

ให้ $T(n)$ คือจำนวนขั้นเมื่อข้อมูลมี $n$ ตัว นับง่าย ๆ ด้วยกฎสามข้อ

- วงวนที่ทำ $n$ รอบ รอบละงานคงที่ ได้ราว $n$ ขั้น
- วงวน **ซ้อน** ให้ **คูณ** กัน เช่น วงในทำ $n$ รอบในทุกรอบของวงนอก ได้ $n \times n$
- งานที่ทำ **ต่อกัน** ให้ **บวก** กัน เช่น วงวนเดียวแล้วตามด้วยวงวนซ้อน ได้ $n + n^2$

วงวนที่แบ่งครึ่งทุกรอบ เช่น `while n > 1: n = n // 2` ทำราว $\log_2 n$ รอบ

## นิยามบิ๊กโอ

เราบอกว่า $f(n)$ เป็น $O(g(n))$ ถ้ามีค่าคงที่บวก $c$ และ $n_0$ ที่ทำให้

$$f(n) \le c \cdot g(n) \quad \text{ทุก } n \ge n_0$$

แปลว่า เมื่อข้อมูลใหญ่พอ $f$ โตไม่เร็วกว่า $g$ คูณค่าคงที่ ตัวอย่าง $f(n) = 3n + 5$ เลือก $c = 4$ แล้ว $3n + 5 \le 4n$ เมื่อ $5 \le n$ จึงได้ $n_0 = 5$ และ $3n + 5$ เป็น $O(n)$ (ดูภาพ) อีกตัวอย่าง $2n^2 + 3n \le 2n^2 + 3n^2 = 5n^2$ ทุก $n \ge 1$ จึงเป็น $O(n^2)$ โดย $c = 5$

ผลที่ตามมาคือ ตัดตัวคูณคงที่ทิ้ง และเก็บเฉพาะพจน์ที่โตเร็วที่สุด บิ๊กโอเป็น **ขอบบน** การบอกว่าค้นหาแบบลำดับเป็น $O(n^2)$ ก็ไม่ผิดตามนิยาม แต่ไม่มีประโยชน์ ควรบอกขอบบนที่แนบที่สุด คือ $O(n)$ นอกจากนี้ต้องระบุว่าพูดถึง **กรณีแย่ที่สุด** กรณีเฉลี่ย หรือกรณีดีที่สุด และอย่าลืม **หน่วยความจำ** ที่อัลกอริทึมใช้เพิ่มด้วย

## ความถูกต้อง: ทดสอบอย่างเดียวไม่พอ

การทดสอบแสดงได้ว่าโปรแกรม **มี** บั๊ก แต่แสดงไม่ได้ว่า **ไม่มี** เพราะทดสอบทุกข้อมูลที่เป็นไปได้ไม่ไหว สำหรับวงวน เราพิสูจน์ด้วย **ค่าคงตัวของวงวน (loop invariant)** คือข้อความที่จริงทุกครั้งก่อนเริ่มรอบ

```python
def find_max(a):
    best = a[0]
    for i in range(1, len(a)):
        # ค่าคงตัว: best คือค่ามากที่สุดของ a[0] ถึง a[i-1]
        if a[i] > best:
            best = a[i]
    return best

print(find_max([31, 27, 35, 29, 40, 33]))   # 40
```

พิสูจน์สามขั้น (ดูภาพ)

1. **เริ่มต้น** ก่อนรอบแรก i = 1 และ best = a[0] ซึ่งเป็นค่ามากที่สุดของ a[0] ถึง a[0] จริง
2. **คงอยู่** ถ้าจริงก่อนรอบ i หลังเทียบ a[i] แล้ว best จะเป็นค่ามากที่สุดของ a[0] ถึง a[i] ซึ่งคือข้อความเดียวกันสำหรับรอบถัดไป
3. **จบ** วงวนจบเมื่อ i = len(a) ค่าคงตัวบอกว่า best คือค่ามากที่สุดของทั้งลิสต์ ตรงกับที่ต้องการ

ต้องแสดงด้วยว่าวงวน **จบได้จริง** โดยหาปริมาณที่ลดลงทุกรอบและลดไม่ได้ไม่รู้จบ เช่น จำนวนตัวที่ยังไม่ตรวจ ส่วนกรณีลิสต์ว่าง a[0] เกิดข้อผิดพลาด ต้องเขียนเงื่อนไขไว้ว่าฟังก์ชันรับเฉพาะลิสต์ที่ไม่ว่าง หรือตรวจก่อน

## ปรับอัลกอริทึมคลาสสิกใช้กับปัญหาใหม่

ครูมีคะแนนที่เรียงแล้ว อยากรู้ว่ามีกี่คนได้ 50 ขึ้นไป แทนที่จะไล่ทีละตัว เราดัดแปลงการค้นหาแบบทวิภาคให้หา **ดัชนีแรกที่ค่าไม่น้อยกว่าเป้าหมาย**

```python
def first_at_least(a, target):
    low, high = 0, len(a)
    while low < high:
        mid = (low + high) // 2
        if a[mid] >= target:
            high = mid
        else:
            low = mid + 1
    return low

scores = [35, 42, 48, 50, 50, 61, 77, 90]
i = first_at_least(scores, 50)
print(i, len(scores) - i)   # 3 5
```

ค่าคงตัวคือ ทุกตัวก่อนดัชนี low น้อยกว่าเป้าหมาย และทุกตัวตั้งแต่ดัชนี high ไม่น้อยกว่าเป้าหมาย ช่วง high − low หดทุกรอบเพราะ `mid` อยู่ระหว่าง low กับ high − 1 วงวนจึงจบ เมื่อ low = high ก็คือดัชนีแรกที่ต้องการ ใช้ราว $\log_2 n$ รอบ ถ้าเขียน `low = mid` แทน `mid + 1` ช่วงอาจไม่หด และวนไม่รู้จบ

## ชั่งสามด้านเมื่อเลือกอัลกอริทึม

ตรวจรหัสซ้ำได้สามทาง เทียบทุกคู่ใช้เวลา $O(n^2)$ แต่ไม่ใช้หน่วยความจำเพิ่ม เรียงก่อนแล้วดูตัวติดกันใช้ $O(n \log n)$ ส่วนเก็บตัวที่เคยเห็นในเซตใช้เวลาราว $O(n)$ แต่ใช้หน่วยความจำเพิ่ม $O(n)$

```python
def has_dup_set(a):
    seen = set()
    for x in a:
        if x in seen:
            return True
        seen.add(x)
    return False

print(has_dup_set([6501, 6502, 6517, 6502]))   # True
```

ความชัดเจนก็สำคัญ ชื่อตัวแปรที่บอกความหมาย โครงสร้างไม่ซับซ้อน และความเห็นที่บอกค่าคงตัว ช่วยให้คนอื่นตรวจความถูกต้องได้ ถ้าข้อมูลมีไม่กี่สิบตัว โค้ดที่อ่านง่ายกว่าอาจดีกว่าโค้ดที่เร็วกว่าแต่อ่านยาก

## ข้อผิดพลาดที่พบบ่อย

- **คิดว่าผ่านกรณีทดสอบแล้วถูกแน่นอน** ต้องคิดกรณีขอบ เช่น ลิสต์ว่าง ค่าติดลบ ค่าซ้ำ
- **ตั้งค่าเริ่มต้นผิด** เช่น `best = 0` ใช้ไม่ได้เมื่อทุกค่าติดลบ ค่าคงตัวไม่จริงตั้งแต่ขั้นเริ่มต้น
- **บวกเมื่อควรคูณ** วงวนซ้อนต้องคูณจำนวนรอบ
- **ลืมว่าบิ๊กโอเป็นขอบบนเมื่อ n ใหญ่** อัลกอริทึม $O(n)$ ที่ตัวคูณสูงอาจช้ากว่า $O(n^2)$ เมื่อ $n$ เล็ก
- **ดัดแปลงทวิภาคแล้วช่วงไม่หด** ทำให้วนไม่รู้จบ
