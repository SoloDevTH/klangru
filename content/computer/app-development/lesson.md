## ค่าไฟบ้านใครแพงที่สุด

นักเรียน ม.3 ห้องหนึ่งสงสัยว่าทำไมค่าไฟบ้านแต่ละคนต่างกันมาก ครูวิทยาศาสตร์สอนแล้วว่าพลังงานไฟฟ้า (หน่วย หรือ kWh) เท่ากับกำลังไฟฟ้าคูณเวลา กลุ่มของมดจึงสร้างแอปให้คนในบ้านกรอกเครื่องใช้ไฟฟ้า กำลังไฟฟ้า และชั่วโมงที่ใช้ แล้วแอปคำนวณพลังงาน ค่าไฟ และแนะนำว่าเปลี่ยนอะไรแล้วประหยัดได้มากที่สุด นี่คือ **แอปพลิเคชันที่บูรณาการกับวิชาอื่น** ใช้ความรู้วิทยาศาสตร์และคณิตศาสตร์ แก้ปัญหาจริงในบ้าน บทนี้รวมทุกอย่างที่เรียนมา ทั้งฟังก์ชัน ข้อมูล และกระบวนการพัฒนาแบบวนรอบ

$$\text{พลังงาน (kWh)} = \frac{\text{กำลังไฟฟ้า (W)} \times \text{เวลา (h)}}{1000}$$

## โครงงานเชิงคำนวณทีละขั้น

1. **ระบุปัญหาและผู้ใช้** ใครเดือดร้อน ต้องการรู้อะไร เช่น ผู้ปกครองอยากรู้ว่าเครื่องใดกินไฟมาก
2. **คิดเชิงคำนวณ** แยกปัญหาเป็นส่วนย่อย (กรอกข้อมูล คำนวณ แสดงผล แนะนำ) หารูปแบบ (ทุกเครื่องใช้สูตรเดียวกัน) เลือกเฉพาะสาระสำคัญ (ไม่ต้องรู้ยี่ห้อ รู้แค่วัตต์และชั่วโมง) และเขียนอัลกอริทึม
3. **ออกแบบ** หน้าจอ ข้อมูลที่ต้องเก็บ และเหตุการณ์ที่ผู้ใช้จะทำ (ดูภาพ)
4. **สร้างต้นแบบ** เริ่มจากความสามารถหลักที่เล็กที่สุดที่ใช้ได้จริงก่อน เรียกว่า **ผลิตภัณฑ์ขั้นต่ำ (MVP)** แล้วค่อยเพิ่ม
5. **ทดสอบและปรับปรุง** ใช้กรณีทดสอบที่รู้คำตอบ และให้ผู้ใช้จริงลอง
6. **นำเสนอ** อธิบายปัญหา วิธีคิด ผลการทดสอบ ข้อจำกัด และสิ่งที่จะทำต่อ

หัวข้อโครงงานที่ดีมาจาก **ความสนใจและความรู้ของตัวเอง** คนชอบดนตรีอาจทำแอปฝึกจับจังหวะ คนชอบชีววิทยาอาจทำแอปบันทึกการเติบโตของต้นถั่วพร้อมกราฟ คนที่อยู่ใกล้ทะเลอาจทำแอปบันทึกขยะชายหาด ความรู้ที่มีอยู่ช่วยให้รู้ว่าผลถูกหรือผิด และมีแรงจูงใจทำจนจบ

## โปรแกรมที่ตอบสนองต่อเหตุการณ์

โปรแกรมในบทก่อน ๆ ทำงานจากบนลงล่างแล้วจบ แต่แอปส่วนใหญ่ **รอเหตุการณ์ (event)** เช่น ผู้ใช้กดปุ่ม พิมพ์ข้อความ ปัดหน้าจอ ตัวจับเวลาครบกำหนด หรือเซนเซอร์ส่งค่ามา เมื่อเหตุการณ์เกิด แอปเรียก **ตัวจัดการเหตุการณ์ (event handler)** ที่ผูกไว้กับเหตุการณ์นั้น ส่วนที่คอยรับเหตุการณ์แล้วส่งต่อเรียกว่า **วงวนเหตุการณ์ (event loop)** (ดูภาพ) วิธีเขียนแบบนี้เรียกว่า **การเขียนโปรแกรมแบบขับเคลื่อนด้วยเหตุการณ์ (event-driven programming)**

ตัวอย่างนี้จำลองแอปค่าไฟด้วย Python ล้วน ใช้ลิสต์แทนเหตุการณ์ที่ผู้ใช้ทำ และดิกชันนารีจับคู่ชื่อเหตุการณ์กับฟังก์ชัน

```python
def on_add(state, watts, hours):      # ผู้ใช้กดปุ่ม "เพิ่มเครื่องใช้"
    state["kwh"] += watts * hours / 1000

def on_clear(state):                  # ผู้ใช้กดปุ่ม "ล้าง"
    state["kwh"] = 0

handlers = {"add": on_add, "clear": on_clear}
events = [("add", 1000, 8), ("add", 60, 5), ("clear",), ("add", 1500, 2)]

state = {"kwh": 0}
for name, *args in events:            # วงวนเหตุการณ์
    handlers[name](state, *args)
print(state["kwh"])                   # 3.0
```

ในเครื่องมือจริง เช่น บล็อก "เมื่อคลิกปุ่ม" ของ App Inventor หรือ `addEventListener("click", ...)` ของ JavaScript ระบบเป็นผู้ทำวงวนให้ ผู้เขียนแค่ผูกตัวจัดการเข้ากับเหตุการณ์ สิ่งที่ต้องระวังคือ ตัวจัดการต้องทำงานเร็ว ถ้าคำนวณนานหน้าจอจะค้าง และผู้ใช้อาจทำเหตุการณ์ในลำดับที่ไม่คาดคิด เช่น กดปุ่มส่งสองครั้งติดกัน

## เรื่องที่ต้องคิดทุกแพลตฟอร์ม

ไม่ว่าจะทำเป็นเว็บแอป แอปโทรศัพท์ หรือโปรแกรมบนคอมพิวเตอร์ ต้องคิดเรื่องเหล่านี้เหมือนกัน

- **ขนาดจอและวิธีรับข้อมูล** นิ้วแตะ แป้นพิมพ์ เมาส์ หรือเสียง ปุ่มบนจอเล็กต้องใหญ่พอให้แตะได้
- **การเชื่อมต่อ** ทำงานได้ไหมเมื่ออินเทอร์เน็ตหลุด
- **พลังงานและประสิทธิภาพ** โทรศัพท์รุ่นเก่ามีหน่วยความจำน้อย
- **ข้อมูลและความเป็นส่วนตัว** เก็บเฉพาะที่จำเป็น ขอสิทธิ์เท่าที่ใช้
- **การเข้าถึงได้** ตัวอักษรขยายได้ สีตัดกัน ใช้กับโปรแกรมอ่านหน้าจอได้
- **ภาษาและวัฒนธรรม** ตัวอักษรไทยแสดงถูก วันที่แบบ พ.ศ.

## ตัวอย่างการคำนวณในแอป

ตู้เย็น 150 W เปิดตลอด 24 ชั่วโมง 30 วัน ใช้พลังงาน $\frac{150 \times 24 \times 30}{1000} = 108$ kWh ถ้าคิดค่าไฟสมมติหน่วยละ 4 บาท (อัตราจริงเป็นขั้นบันไดและมีค่าไฟฟ้าผันแปร) เป็นเงิน 432 บาท แอปควรบอกด้วยว่าใช้อัตราสมมติ เพื่อไม่ให้ผู้ใช้เข้าใจผิด

## ประเมินโครงงาน

โครงงานที่ดีไม่ได้วัดที่จำนวนความสามารถ แต่ดูว่า

- แก้ปัญหาของผู้ใช้จริงได้ไหม มีหลักฐานจากการทดสอบหรือไม่
- ใช้ความรู้วิชาอื่นอย่างถูกต้อง เช่น สูตรพลังงานไฟฟ้าถูก หน่วยถูก
- อัลกอริทึมและโค้ดอ่านเข้าใจ แบ่งเป็นฟังก์ชัน มีกรณีทดสอบ
- บอกข้อจำกัดอย่างซื่อตรง เช่น ใช้อัตราค่าไฟสมมติ
- ให้เครดิตโค้ด ภาพ และข้อมูลที่นำมาใช้

## ข้อผิดพลาดที่พบบ่อย

- **ตั้งเป้าใหญ่เกินเวลา** ทำได้ครึ่ง ๆ กลาง ๆ ทุกอย่าง ควรเริ่มจาก MVP
- **ลืมหน่วย** เช่น ลืมหาร 1000 ได้ค่าไฟเป็นแสนบาท
- **คิดว่าผู้ใช้กดตามลำดับที่ออกแบบเสมอ** ต้องรับมือการกดซ้ำหรือข้ามขั้น
- **เขียนทุกอย่างในตัวจัดการเดียว** ยาว แก้ยาก ควรเรียกฟังก์ชันย่อย
- **ไม่ได้ให้ผู้ใช้จริงลอง** ก่อนนำเสนอ
